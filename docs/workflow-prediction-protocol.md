# 业务完整工作流预测：冻结协议

本轮不修改既有模型权重、CP-SAT、官方 PIBT 或 LaCAM3。事实执行仍由 `BusinessSimulator` 和设备、容量规则决定。以 [config.json](../experiments/workflow_prediction/config.json) 冻结场景、3 个粒子、5 步、4 个候选和求解预算；所有设备、任务及时间均为仿真假设。开发集沿用 PR #12 场景；确认集使用相同公开地图、事先检查过任务表不与以往重复的新种子，因此只能称为**已见地图上的新任务表确认**，不能称为未见布局或真实医院验证。各故障/容量变体共用同一任务表，按地图与种子聚合，不能把同一轨迹的窗口当作独立样本。

可见输入仅为当前观测与 `PublicBusinessRules.workflows`。若某次预测把一个已知阶段从未完成转为完成，仅在下一预测观测边界释放模板中的后继，继承公开样本属性、设置新 ID、等待状态和空机器人；同一预测步不能分配它。最后阶段完成后不生成后继。服务完成仍分别由现有规则、PETS 或结构化头预测；未来外生到达、故障和隐藏倒计时不可输入。业务专用校验复用并保留通用固定 ID 检查，同时核验新增阶段的来源、时间、属性、串行约束、位置与容量。

新系统入口为 `WorkflowDynamics` 与 `WorkflowPolicy`：前者包裹原有服务/运动模型，后者启用业务递推和工作流评分。`BusinessPolicy` 与 `CapacityDynamics` 的默认语义仍是旧版，供历史复现和本轮对照使用；不能只创建旧入口就声称已经启用完整工作流预测。配置中显式给出的样本类型、包装、温度条件和规则配置由编译器传递给各实际阶段；优先级只在当前输入本来包含时继承，模拟器本身没有新增优先级机制。

新评分对起始时**已知的完整业务任务**逐个计数。第一项是预测窗口内未完成任务数之和，加窗口末估计的剩余运输距离与有效服务工作量：每步、每格和每服务步均按一单位，沿用既有评分的名义成本解释，并非真实业务成本或调参结果。已观察有效服务进度可扣除；无法观测时按零扣除。尚未释放但属于已知任务的阶段，只取公开路线和服务先验；不把陌生外来任务加入评分。第二项是共享资源同时需求超过容量的代理，第三项是剩余距离；它们仅作依次平局判定，不把同一次等待重复累加。无真实 FIFO 队列假设。保留原始 `workload_score()`。

闭环比较：最近优先；CP-SAT + 规则 + 旧转移/旧评分；CP-SAT + 规则、PETS、结构化头分别使用新转移/新评分。三种新方案共享候选生成、模型调用预算、评分、预测运动后端及外生扰动。固定事实状态另做 2×2 离线消融（旧/新阶段转移 × 旧/新评分），三种模型使用同一候选集合；候选结果分别从完全相同的事实前缀独立重放，之后由最近优先继续。该离线完整结果不可反馈给在线策略。

事实预测分别统计：旧固定实体指标（沿用原 `eligible_windows` 及其分母）、业务动态联合指标、一步/三步/五步覆盖、后继阶段释放和服务完成差异。动态窗口只在首步允许事实动作，之后无事实新分配；排除未见外部任务和设备状态变化。按预先规则每 5 个合格窗口取一个，并额外纳入有合法后继释放的合格窗口；同时报告候选窗口、排除原因及选中数。将“预测服务完成不对”与“服务完成预测相同时业务释放/资源更新仍不对”分开，后者是工程错误，不通过注入未来服务结果来掩盖。

小规模验收发现旧容量适配在清理被拒绝机器人虚假服务进度后，可能保留站点的虚假服务关系；新业务层基于同一 `rebuild()` / `capacity_view()` 重新计算关系并加入回归。开发集首次双次运行还发现无序任务集合造成浮点末位不一致，已固定遍历顺序，未调整公式、种子、模型或场景；先前日志保留在本轮证据目录。
