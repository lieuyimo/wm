# 服务预测到调度决策：实验协议

从尚未合并的 PR #9 head `96e5f4c1e1626171682549e796b774c14e91cad2` 出发；不改动其代码、数据和检查点。加载 `examples/evidence/service-dynamics-20261109/sequence.pt`，使用训练报告中冻结的服务阈值 0.60；先验证其文件、数据清单及模型合同源码哈希。不训练模型、不使用 GPU。

## 第一阶段：原评分与窗口

原 `RolloutPolicy` 对每个可行**单一分配**按原候选顺序取前 8 个，第一步施加该分配、后续预测不再分配，分别取 3/5/10/20 步；只对候选任务计算完成状态和剩余几何距离，最小分数并列按候选顺序取第一项。它不主动等待、也不组合多个分配；旧 `decision_value.batch_candidates` 是另一个接口，提供等待及多分配，但不是 PR #9 的 `RolloutPolicy`。本轮主要分数比较严格复用前者；额外独立重放一次空分配，报告等待相对于有限单分配最优结果是否有价值，但不擅自为原评分编造等待分数。

地图 Tartu / clinic；每个布局各 2 个开发种子、2 个独立确认种子。按任务签名排除 PR #8 数据和 PR #9 数据（含 normal/burst），并排除本轮不同种子间重复；只检查起终点及释放时间，不查看服务或调度结果。预先从升序候选池选到：开发 Tartu 31002、31005，clinic 32000、32001；确认 Tartu 33000、33003，clinic 34000、34001。每个种子使用 PR #9 的 normal、burst、outage_processing、outage_arrival；任务、站点、20 步故障和站点角色均为仿真假设，固定 `make_round2_cases`。保留普通及故障前/中/后决策点，采用 PR #6 已固定的 `chosen_decisions` 规则，不按预测效果挑选。以完整布局/种子为独立簇，而非把四种场景、时间步或候选当独立样本。

每一决策点先独立重放每个候选和等待：完全复现事实前缀、验证隐状态历史一致，强制首个候选后，复用 PR #6 的 `replay_branch`，所有分支均以相同的最近优先多分配匹配继续。线上闭环则和 PR #9 一样每次只分配一个任务；这两种分配粒度不同，离线损失与闭环表现必须分别解释。任务到达、故障和按照 `(seed, sample, phase, station)` 产生的服务时长一致。记录候选自己的实际短期服务完成事件和完整样本结果，完整流转只做有限候选的事后参考；存在未完成或缺失数据时标记删失，不将其伪装成完整结果。

三个 20 步模型分别使用修正规则、PR #9 规则运动+神经服务、离线服务时长参考，分别在同一轨迹中抽取 3/5/10/20 步并计时。离线参考从**各候选自身完整重放**中的 `service_started/service_finished` 事件及已发生的站点可用状态重建每个已知样本在各阶段的有效服务时长；不读取模拟器私有剩余倒计时。它可以事后得知**窗口以外**才完成的服务总时长，因此比“仅见到窗口内事件”更强，只是特权离线诊断，不能部署，也不能称为完全正确的未来状态：运动规则仍会有误，未知未来站点变化仍假设维持当前状态。它仅预测初始已知任务；不读取未来新任务或未来故障计划来控制预测。每候选自己的实际短期服务事件另存用于计算召回和精确率；候选自己实际的整段短期状态评分作为更强的离线完整状态参考，并明确包含未来外生影响，不冒充服务预测。

若给定候选服务在完整反事实中未完成或无法匹配，则该离线服务参考标记不可用，不以其他候选的事实值补齐。分析每个窗口的评分并列、动作差异、候选对排序错误、相对于有限候选完整流转的决策损失、服务事件召回/精确、已知实体联合状态误差和 CPU 耗时。平均值先按场景内决策点、再按布局/种子簇聚合，按布局分层重采样 2,000 次；每张地图仅两个种子，区间仅作探索。

## 第二阶段：冻结新评分后独立确认

先运行并检查开发集的原评分窗口对照；之后在本文件追加冻结的新评分公式和窗口选择规则，再运行同一开发集的新评分与此前未查看结果的确认集。评分只能用当前/预测状态、可观察服务进度和历史估计，不读取隐藏时长或未来外生事件；不得把 FIFO 排队当作既有业务事实，不重复计入同一段等待。在线闭环只运行规则/混合模型与原/新评分四组；两类特权离线参考只能在独立反事实结果上评分，绝不作为线上决策器或伪装为真实可部署闭环。

### 开发集原评分诊断后的冻结设置

原评分开发集 40 个决策点中，3 和 5 步三个预测器及真实短期状态均选择相同动作；10 步服务时长参考相对规则改变 3 次，20 步改变 6 次。服务时长参考的场景簇平均完整流转损失在 3、5、10、20 步分别为 1.730、1.730、1.369、1.170 仿真步；20 步混合模型的已知实体联合正确比例只有约 0.093，平均每候选 CPU 推演约 7.4 ms。因此本轮固定 **20 步**进行评分对照，独立确认必须同时报告预测误差和额外成本；这些开发结果不说明 20 步一定能在线改善。

新评分按字典序最小化 `(W + R, C, D)`，系数均为 1，不再拟合。仅考虑决策起点已知的任务：

* `W`：窗口内每一步尚未完成的已知任务数之和，单位为任务·仿真步。它计入等待和运输阶段的未完成成本，每个任务每步只计一次。
* `R`：窗口末每个未完成任务的估计剩余静态行走步数与尚需服务步数之和。已分配任务使用负责机器人位置；未分配任务使用最近机器人的距离；已取样任务只计送达，未取样任务计取样和送达。服务估计采用该站可观察的历史有效均值，缺失时采用现有公开先验；如果机器人已在对应站点且有效进度可观测，减去已完成的有效服务步数，未知进度按零处理。`R` 只估计窗口**之后**的工作，不额外加计已在 `W` 中累计的等待；它忽略并行、未来等待和未知故障，不是实际完成时间或可证明下界。
* `C`：仅作为主分数相等时的资源竞争**代理排序键**，不再计作等待时间。每个站以已知未完成任务的下一目标计算需求数；站点被不属于这些需求任务的机器人占用时再加一；累加 `max(0, 需求−1)` 和“当前不可用且有需求”的指标。它不代表 FIFO 排队、也不表示实际延迟。
* `D`：已知未完成任务的静态剩余行走距离之和，仅作为进一步并列排序键。所有距离、服务估计及任务状态来自当前或预测状态，未来新任务和故障计划不输入模型。

新旧评分始终共用候选集合、模型推演、窗口、扰动和离线后续策略；不根据确认集改权重或公式。完整状态参考、服务时长参考分别单列，均仅用于独立重放后的离线诊断；原评分保持不变。

### 对后续分配不一致的补充检查

完成原定确认集后，审查发现 PR #9 模型推演只在首步分配，之后不再分配；而离线真实分支以最近优先多分配继续。二者产生的状态差异包含后续动作不一致，不能全部归因于状态预测误差。保留原定结果和评分、窗口不变，另做**探索性**对照：模型预测的每一步也在其自身预测状态上执行相同的最近优先匹配，不能读取真实分支未来动作或事件；与每个候选自己的独立反事实结果比较。由于是在观察首轮确认结果后增加的诊断，不能将其当作事先注册的独立确认，也不据此修改模型或评分。新的实验代码必须核对候选动作及真实完整流转与首轮记录一致。

原定在线运行已记录每场景 P95；为避免把“各场景 P95 的均值”误写成“全部决策的 P95”，补充记录每次调用耗时并重跑相同在线配置，单独报告合并的描述性 P95。该改动不改变动作、评分、模型或种子，先前运行结果保留。
