## 数据和故障：先固定，后运行

复用第二轮公开地图适配和故障生成规则 `make_round2_cases`，不重新设计医疗流程。每个种子均使用 normal、burst、outage_processing、outage_arrival 四个场景及 nearest/world 两种事实采样行为。burst 的六个释放时刻为 0、0、2、4、8、12，同源目标任务竞争是仿真假设；处理中断相对于**事先的无故障 nearest 参考运行**首次取样服务开始后 1 步发生，到达中断从其首次送达服务前 1 步开始，均持续 20 仿真步。这是为了覆盖服务的固定实验设计，实际样本等待必须事后记录，不能声称真实医疗故障分布；世界模型看不到参考探针及未来故障计划。normal 保留原合成到达作为对照，burst 是故障场景配对的无故障基线。不会根据策略效果反复调整故障。

种子候选池：训练 Tartu 21000–21199 取 4 个；验证 Tartu 23000–23199 取 2 个；同图测试 Tartu 25000–25199 取 2 个；跨图测试 clinic 26000–26199 取 2 个。按上述 split 和 seed 升序检查 normal/burst 的 `(布局, 起点, 终点, 释放时间)` 任务表，仅根据任务签名（不运行、不查看模型或场景结果）跳过与 PR #8 旧训练/验证/测试或已选新种子重复的任务表；每个新种子的两个任务表均须与其他新种子不重复。选定后停止选择并归档清单；不足则停止，不按实验效果换种子。相同种子的正常/异常和行为策略必须处于同一 split。保留完整场景配置、源地图哈希、episode 原始数据校验和、受故障实际影响的服务会话、等待步数、恢复时未完成任务数、占用目标竞争代理（非 FIFO 队列）。如果目标事故没有产生等待，保留该记录，不按结果删选。

仅事实执行轨迹用于训练；观测格式和历史进度恢复复用现有验证器。动作和特征只含当前已释放任务、机器人、站点、过去的可观察历史和当前分配；未来事件、随机状态、真实剩余服务时间、反事实未执行结果及 case 元数据不可进入特征。按布局/seed/任务表隔离训练、验证、测试；先用少量 CPU 固定数据做端到端验证，不使用无目的参数搜索。

## 模型消融

保持 PR #7 的 4,642 参数实体集合架构，CPU、种子 123、batch 128、Adam 学习率 0.001、5 个 epoch 上限；各变体使用相同初始化、训练数据及批次顺序，按验证集原始一步损失选 checkpoint。逐项记录运行时、训练/验证损失、样本数及 checksum。

1. **原网络**：原 `motion` 交叉熵 + `service` 二元交叉熵，完成阈值 0.5。
2. **类别权重**：仅服务完成正类使用训练集中负类/正类数量比（上限 10）；保留运动损失及阈值 0.5。比例只从训练数据计算，记录数值。
3. **验证阈值**：使用类别权重模型，在独立验证集服务样本上对阈值 0.05–0.95、间隔 0.05 做有限校准，最大化服务完成 F1；平分时优先接近 0.5、再选较小值。阈值仅由验证集决定并冻结，测试集不用来调参。
4. **3 步辅助训练**：同一加权目标额外加入权重 0.3 的三步服务完成事件 BCE。以当前已知状态推演未来 3 个有效服务步的 hazard，标签来自该事实轨迹的已发生服务结果；窗口如果在完成前发生不可观察的未来站点变化或被截断则只用于一步训练，不把未来可用状态输入模型。假定服务继续且站点可用，实体上下文保持当前观测、服务有效经过时间逐步增加。它是有条件的三步生存代理，不是完整系统 BPTT；三步模型再按相同验证集规则校准一步阈值。
5. **职责分离**：同一三步训练并校准的网络只决定服务完成；机器人位置来自既有修正规则路径。保留完整神经运动模型，两者共享权重和服务阈值。保留纯修正规则作为强基线。

上述训练因素不混称独立因果效应：逐项比较原网络→加权→加权加校准→加权、3 步辅助加校准；最后比较相同网络的完整神经运动与规则运动版本。若训练未充分、正样本不足或验证结果不稳定，保留负结果并说明。

## 测试与闭环

相同初始状态、候选顺序、候选上限 8、horizon 3、同一 `RolloutPolicy` 原评分、相同外生任务/故障及确定的服务随机抽样；每次决策选一个 assignment。闭环包含纯规则、原完整神经、加权、加权校准、三步校准完整神经以及相同服务网络+规则运动，前四种重点比较包含请求的四个配置，不把 Simulator 原生 `nearest/world` 的多任务分配当作严格配对。不同策略执行后状态可能不同，所以只保证相同协议及外生事件；另外在事实同一观测上记录各模型对完全相同候选的选择。计时报告实际 CPU 推理，不假设 GPU 延迟。

在独立测试轨迹上报告一步已知机器人位置/任务状态联合正确率、服务完成召回与精确率、3/5 步误差及符合既定条件的窗口覆盖；闭环报告完整完成数、平均任务流转、实际站点等待、资源竞争代理、回退、安全和每次调度耗时。按独立布局/seed 配对并列出各场景，不将多条相同场景轨迹和时间步视为独立样本。主要结论按故障/正常分解。因 CPU 功能实验样本少，结果仅供方向判断，不要求显著性或强行取得正向结果，也不能直接证明真实系统效果或需要 GNN。

为限制 CPU 成本，一步指标覆盖全部事实转移；3/5 步按每个 episode 的符合条件窗口的自然时间顺序，每 5 个窗口取第一个，所有模型共用同一抽样，记录总候选、符合条件和实际抽样数量。这个固定抽样在任何测试评价前确定，不按模型结果挑选。

补充诊断：首次得到总表后发现“三步训练并校准”同时改变了训练目标与阈值，无法分别解释它们的作用。为满足逐项消融，额外评估**同一个三步检查点**在固定阈值 0.5 下的预测和闭环，再与其验证集选出的 0.6 阈值对照；不重新训练、不选择新阈值，也不改变原先的主要比较。该补充发生在查看首轮测试结果之后，应标明为探索性分析。
