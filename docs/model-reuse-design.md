# 样本转运世界模型：复用与预训练迁移方案

状态：设计候选；已完成预训练快分支的 CPU 权重映射、输出一致性，以及初始化文件保存和严格重载检查；尚未完成世界预测分支训练、样本转运适配或 GPU 验收。目标是复用成熟模型完成毕业设计，不预设必须原创网络或从随机权重训练全部模块。

## 现状与需要纠正的判断

仓库已实现并训练过一个 PyTorch 示例网络，预测已知机器人移动和站点服务进度，并在合成场景中参与过候选调度；它仅有 338 个参数，主要用于验证接口，不是论文最终模型。此前对这个网络做的分钟级训练排期不能用于估计下面的多百万参数模型。

原本应在建设仿真和训练接口的同时，调查已发表模型和可用权重。模型选择耽误了时间；没有复现完整分层模型，不意味着必须从零发明或训练模型。

## 候选：复用 MAPF-World 与 MAPF-GPT 预训练部分

1. [MAPF-World 论文](https://arxiv.org/html/2508.12087v3)提出共享主干和快、慢两个预测分支：快分支提出动作，慢分支预测局部状态及相邻机器人的动作意图。其定位是局部多机器人路径规划，不能直接代表样本任务调度和站点业务规则。
2. 与论文同名的[公开代码](https://github.com/Fibonaccirabbit/MAPF-World/tree/f18c879646248e79345c4c05c2ecf396f26b3437)可读取；[许可证](https://github.com/Fibonaccirabbit/MAPF-World/blob/f18c879646248e79345c4c05c2ecf396f26b3437/LICENSE)为 MIT，包含多方原始版权声明。仓库引用的外部地图数据另受其来源许可证约束。
3. 截至 2026-11-08，仓库 README 示例引用 weights/mapf-world-3M.pt，但检查该固定提交的递归文件树和 GitHub Releases 时没有找到权重文件或可下载发布。此结论只表示当前检索范围内未找到，不能断言作者没有在其他地方提供。
4. [MAPF-GPT](https://github.com/CognitiveAISystems/MAPF-GPT)是多机器人路径规划策略模型，作者在[模型仓库](https://huggingface.co/aandreychuk/MAPF-GPT)公开了 2M、6M 和 85M 权重，标注 MIT。2M 文件约 19.1 MB。MAPF-GPT 是动作策略，不能把其已训练的权重直接称为已训练的 MAPF-World 预测分支。

### 已发现的参数对应线索

MAPF-World 的 [FastAndSlow_S_2](https://github.com/Fibonaccirabbit/MAPF-World/blob/f18c879646248e79345c4c05c2ecf396f26b3437/model/world.py) 使用 5 层、5 个注意力头、160 维的快分支共享主干，上下文长度 256；[MAPF-GPT 2M 训练配置](https://github.com/CognitiveAISystems/MAPF-GPT/blob/d6307447ddc6bc2b7bf5da4f81d4e0707fbc8fa3/experiment_setup/config-2M.py)也列出 5 层、5 个注意力头、160 维、256 上下文。这是迁移试验的代码级线索；二进制检查点的 CPU 验证结果如下。

基于两份源码，拟检查以下名称对应关系：

| MAPF-GPT 参数前缀 | MAPF-World 候选参数前缀 |
| --- | --- |
| transformer.wte | fast_token_embedding |
| transformer.wpe | fast_position_embedding |
| transformer.h | shared_backbone |
| transformer.ln_f | fast_norm |
| lm_head | lm_head |

加载器必须逐项检查键名、张量形状、位置编码及输入词表，处理原实现可能存在的 _orig_mod. 前缀，并检查 token embedding 与输出层的权重共享。不能仅用 strict=False 忽略不匹配后声称迁移成功。对完全相同的输入与 eval 模式，还应比较迁移前后的快分支输出是否数值一致。

MAPF-World 的[训练入口](https://github.com/Fibonaccirabbit/MAPF-World/blob/f18c879646248e79345c4c05c2ecf396f26b3437/train/main.py#L720-L726)对初始化权重使用 strict=True；它不能被当作已支持直接加载另一架构的 MAPF-GPT 检查点。应在本项目的适配层实现可审计的名称映射，不修改上游仓库。

**目前已验证复用的部分是快分支及共享主干。** 慢速世界预测分支和新增的样本、站点适配部分尚无相应预训练证据，仍需选择初始化方式并用目标仿真数据训练或微调；实际效果须实验验证。

## 已完成：预训练快分支 CPU 兼容性测试

[GitHub Actions 42430274676](https://github.com/lieuyimo/wm/actions/runs/42430274676) 固定下载两份上游源码和公开的 MAPF-GPT 2M 权重，以 SHA-256 校验权重，使用 PyTorch 的 weights_only 模式在 CPU 加载。检查点实际配置是 5 层、5 头、160 维、长度 256、词表 67。按上表映射后，34 个快分支张量的名称和值均通过检查，输入嵌入和输出头仍共享权重；对同一批 2×256 测试 token，迁移前后 logits 的最大绝对差为 0.0。测试还导出了初始化检查点，按原模型结构严格重载后再次比较，最大绝对差仍为 0.0；该文件不含已训练的世界分支，也不是训练中断恢复检查点。

[紧凑验证结果](../examples/evidence/mapf-reuse/fast-transfer-cpu-42430274676.json)及[完整工作流日志](../validation/logs/mapf-pretrained-action-42430274676.log)已归档；权重未提交。测试输入仅验证参数和快分支前向等价，不等于已接入样本转运仿真，也不证明预测效果、慢分支已经预训练或 GPU 可运行。

### 本地生成初始化文件

分支中提供验证与导出工具。准备好固定版本的两份上游源码和经 SHA-256 校验的公开权重后，可在 CPU 上运行：

```bash
python validation/mapf_world_reuse/check_pretrained.py --mapf-world /path/to/MAPF-World --mapf-gpt /path/to/MAPF-GPT --checkpoint /path/to/MAPF-GPT-2M.pt --output runs/mapf-transfer/evidence.json --save-initialized runs/mapf-transfer/mapf-world-init.pt
```

该命令会拒绝覆盖已存在的输出，具体版本、依赖和校验值见 [CPU 工作流](../.github/workflows/mapf-world-transfer-smoke.yml)。上游训练入口是否能够以项目数据完成微调尚未验收；生成的文件只能作为初始化，慢分支和站点任务适配仍需训练。

## 本项目拟采用的分层组合

1. **任务及站点层**：保留当前可观察的样本、机器人、站点状态及可选截止时间。系统生成当前可执行的机器人—样本候选分配；缺失的临床期限不补造。
2. **局部多机器人层**：优先使用 MAPF-World 公开实现及可验证迁移的预训练主干，对机器人局部状态和邻居意图进行动作条件预测。现有的可行性检查和离散移动约束仍由仿真器执行。
3. **样本转运适配层**：把候选分配转换为机器人当前目标，补充已知工作站可用性、服务进度与任务状态，预测对交付有用的状态变化。该适配层是项目需要开发的部分，不能声称开源权重已经理解实验室业务。
4. **方案选择与执行**：对相同候选集合进行有限步预测、比较和选择，发生模型异常或约束冲突时使用已有回退机制；记录模型调用、选择、执行和结果。安全检查、异常回退和多步预测效果均需再验收。

MAPF-World 原始动作是网格上的等待、上下左右，当前转运调度动作是机器人—样本分配；两者不是同一个接口。优先用现有网格示例检查编码与权重迁移，再研究如何在有来源的医院有向路网上正确表达可通行区域和单行约束。医院图中的航点编号不是二维网格坐标，不能凭编号差值虚构上下左右或障碍物。

## 数据与评估

- 本项目现有 96 场、21,269 条转移是合成仿真数据，其中 48 场训练、16 场验证、32 场分属两个测试集。它们适合接口验证和初步微调，不应声称等同于作者的大规模预训练数据。
- 原始转移提供实际执行的分配及下一观测，不能把未执行候选动作的结果伪造成监督标签。当前未释放任务、未来故障和真实剩余服务时间不能进入输入；训练和测试按场景及任务时间表隔离。
- 先比较：现有规则调度、已发布的 MAPF-GPT 动作策略参考、未迁移的同结构模型、验证通过后的迁移模型。前三者是对照，不应弱化其实现；必须报告可执行约束、相同任务和扰动、计算预算及显存。
- 指标分开报告预测准确性、任务完成/耗时、可能的超时、停滞与恢复、计算时间以及离散约束违规。当前规则和仿真不能证明真实医院物理或临床安全。

## 资源与已知限制

[MAPF-World 论文实验](https://arxiv.org/html/2508.12087v3)报告了约 2.7M 参数的模型，以及 80M 转移数据、单张 V100 和 64 个 CPU 核心条件下约 48 小时的训练；论文还提及快分支使用更大规模的动作样本。这是作者的实验配置，不是本项目迁移微调所需时间，不能按样本数直接线性换算成 4070 或 V100 的耗时。

公开实现的默认小模型配置使用 bfloat16，训练入口在设备不支持时建议改用 float16；V100 和 4070 Laptop 的实际精度、显存及兼容性都需要在用户机器上检查。先以小批次做 CPU 功能测试，再由本地 GPU 测量显存和每轮时间；当前不能声称 8 GB 已实测可用。

## 下一步验收

1. 已固定开源提交与来源、许可证，安全取得并校验 MAPF-GPT 2M 权重；大权重未提交到本仓库。
2. 已在 CPU 上验证快分支 34 个张量的映射、形状、共享权重、相同输入输出以及初始化检查点重载；后续仍需验证真实网格输入及训练适配。
3. 在网格仿真上实现可观察数据编码、预测和有预算调度的适配，完成无未来信息泄漏、训练/预测、保存/加载和闭环检查。
4. 梳理公开医院地图转换的证据及误差，决定可复用权重的范围，再用用户本地 GPU 完成小批次训练和性能实测。
5. 比较迁移、非迁移、规则等方案，更新可视化和论文材料；不以事先假定模型获胜为目标。

以上均为候选设计和待验收工作，并不是已完成的模型实现或已确认的训练效果。
