# RHWM ETM：在修复后的严格 CPU 预算下验证事件触发的自适应预测时域

日期：2026-11-12  
状态：**真实独立在线实验完成，轻负载计算节约成立，高负载预算与跨场景调度收益未改善，暂不晋升默认策略**。

## 1. 来源与真实移植

- Wang, Ren and Zheng, *Robust Nonlinear MPC With Variable Prediction Horizon: An Adaptive Event-Triggered Approach*, IEEE Transactions on Automatic Control 68(6), 2023, DOI [10.1109/TAC.2022.3200967](https://doi.org/10.1109/TAC.2022.3200967)：借鉴状态触发与可变预测时域以减少无必要预测；本实验只是**面向样本转运的工程改编**，没有复现论文鲁棒稳定性证明、约束控制律或物理非线性动力学。
- Russell and Wefald (1991), *Principles of Metareasoning*, DOI [10.1016/0004-3702(91)90015-C](https://doi.org/10.1016/0004-3702(91)90015-C)：借鉴“额外计算应有改变外部动作的价值”的框架，并未实现其最优计算价值估计。
- Chua et al. (2018) PETS 的有界粒子预测仅使用本仓库原有 RHWM 接口，不迁移其 CEM、训练算法或神经结构。
- 复用 **Draft PR #37 已验证的 post-candidate 预算门禁修复**及人工时钟单测：所有固定 V4-H5/V4-H20/Rule-H20 候选在最后一次预测结束后仍要检查 0.5 CPU 秒。**预测超预算时禁止应用新选案**。单个原子 rollout 不可打断，故计算实际耗时可能仍超过预算；这里的保障是安全回退而非硬 wall-clock SLA。

**唯一实验性新增策略**：原冻结 V4，先 H5/P1 对同一批 CP-SAT 合法提案评分；若 H5 预计完成样本数打平且当前至少3个未完成业务作业，追加 H20/P3；如额外推理不能在 CPU 预算内完整完成，回退已获得的H5选择；H5也不能完成则回退CP-SAT首选。H5与H20都按预计完成工序数最多排序，平局维持CP-SAT首选。不训练、不添加自造评分权重、不改模型源代码或底层路径/工作流。

- 每个场景执行同样事实系统，分别运行5条在线策略：原 CP-SAT、Rule-H20、冻结 V4-H5、冻结 V4-H20、自适应 V4-H5→H20。共同随机外因、同候选生成器、同任务与共享资源、相同 service-duration keyed seed；每条轨迹真实运行原 BusinessSimulator。

## 4. 计算预算的真实对照

| 每类6组 | 固定V4-H20 平均完整场景CPU秒 | 自适应平均完整场景CPU秒 | 固定H20记录超预算次数 | 自适应记录超预算次数 |
|---|---:|---:|---:|---:|
| light | 0.178 | **0.040** | 0 | 0 |
| medium | 0.686 | 0.672 | 0 | 0 |
| heavy | **2.371** | 2.413 | **8** | 10 |
| shift | 2.086 | **2.048** | **0** | 1 |

- **轻载 CPU 降低约 77.5%**，且全部6组完成时间无差异；这是当前事件触发模式最明确的实际价值。
- 中负载 CPU 降低约2.1%，业务结果相同。
- **高负载 CPU 约增加1.7%**，0.5 CPU秒预算触发次数反而增加，目标“有限预算下加速重要决策”未成立。
- shift CPU 下降约1.8%，但预算溢出从0变1。该条件下原V4-H20实际完成时间均值**比CP-SAT更差0.5tick**，所以保留预测信息不等于产生调度净益。
- 单次同步预测不可被此实现强制中断；预测预算越界有记录，且已验证禁止使用超限候选。CPU为GitHub runner统计，不能当成企业实际硬实时保证。

## 5. 阶段判断与后续

**方法借鉴与世界模型系统集成 GO；高负载计算效率和普适调度收益 NO-GO。**

本实验表明可以对短时/长时世界模型预测做公开状态触发管理，不需要新网络。但“先 H5、打平时再 H20”在高负载可能增加冗余计算，不可把它写成解决了高并发调度 CPU 瓶颈。

后续应针对高负载中**多个候选×多个粒子×每 tick重复调用 CP-SAT 续调度**的真实计算路径，检索并迁移已有 MPC/求解器增量计算、批量规划或 anytime 搜索实现，再在另一个固定新数据组验证。不要在这些已测试场景上调节“>=3作业”门槛或再次刷 seed。训练/环境保存仍按照 PR31 已固定流程执行；本轮未触发新的后训练。
