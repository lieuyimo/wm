# 服务动力学：故障覆盖、模型消融和调度对照

本轮基于 `main` 的 `0364a63447b7ecc67ea1872ba938afb3536fefc1`，不合并 PR #8；其 A100 基线已[原样冻结并校验](pr8-baseline-provenance.md)。实验协议和故障参数事先固定在 [service-dynamics-protocol.md](service-dynamics-protocol.md)。以下故障是真正在仿真中中断服务、导致等待和积压的事件，但不是真实设备或临床数据。

## 数据、信息边界与训练

数据包含 80 条完整场景/行为轨迹、18,358 条事实转移：训练 32 条轨迹、8,401 次转移；验证 16 条、4,052 次；Tartu 测试 16 条、4,018 次；clinic 测试 16 条、1,887 次。训练、验证和测试按布局与种子及完整任务表隔离，同一场景的 normal、burst、处理中断、到达中断及 nearest/world 两种事实策略留在同一组。独立测试只有每张地图 2 个种子；相同种子的场景、策略和时间步不能当作独立样本。确定的种子、输入源哈希和每条 episode 校验和见[数据清单](../examples/evidence/service-dynamics-20261109/dataset-manifest.json)。

| 数据划分 | 处理中断的实际等待 | 到达中断的实际等待 | 中断恢复时未完成任务合计 |
| --- | ---: | ---: | ---: |
| 训练 | 160 步 / 8 条轨迹 | 152 步 / 8 条 | 96 |
| 验证 | 80 步 / 4 条轨迹 | 76 步 / 4 条 | 48 |
| Tartu 测试 | 80 步 / 4 条轨迹 | 76 步 / 4 条 | 48 |
| clinic 测试 | 80 步 / 4 条轨迹 | 76 步 / 4 条 | 48 |

上表恢复时未完成任务包括等待、搬运及处理中的任务，是积压代理，不是工作站 FIFO 队列。正常场景服务故障等待均为 0；集中到达的无故障 burst 也保留。处理中断来自事先约定的无故障 nearest 参考运行，故障持续 20 步；选择种子只检查任务签名，不依据模型效果。逐场景配置、受影响服务与资源竞争代理见[覆盖数据](../examples/evidence/service-dynamics-20261109/dataset-coverage.json.gz)。与 PR #8 的 10 个训练暂停步相比，本轮有更多**实际发生的模拟暂停**，但由于任务和场景设计不同，这不是模型增益的独立因果估计。

输入只含当前观测、当前分配、已释放任务、已观察服务历史和地图；未来任务、站点故障时间表、随机抽样及真实剩余处理时长不进入模型。训练数据只记录事实执行动作。工作站当前不可用时由规则保持服务暂停，神经服务头只在当前可用时预测完成；三步事件训练的未来故障和截断用于离线标签删失，不作为输入，因此本轮**没有学习预测未知故障发生或恢复时刻**。

固定 5 epoch、batch 128、Adam 0.001、种子 123，三个模型同初始化、数据和批次；按验证集未加权一步损失选检查点。三个模型的最优检查点均出现在预定上限第 5 epoch，不能认为已经充分收敛。训练有 352 个服务完成正例和 668 个负例，正类权重为 1.898；三步辅助窗口 734 个正例、278 个负例、8 个删失。加权模型验证 F1 选择阈值 0.50，三步模型为 0.60；校准只使用验证集。三个 CPU 检查点、运行配置、代码与数据哈希保存在[证据目录](../examples/evidence/service-dynamics-20261109/)，与 PR #8 原始证据分开，输出目录禁止覆盖。

## 预测与逐项消融

服务完成召回和精确率从当前可用、机器人已到目标站的全部事实服务机会计算，包含当前刚分配并在同一步完成的情况。一步联合正确要求所有当前已知机器人位置和任务状态同时正确；数字是各轨迹的汇总，不把事件视为相互独立。以下是独立测试集：

| 模型 | Tartu 一步联合 | Tartu 服务召回 / 精确 | clinic 一步联合 | clinic 服务召回 / 精确 |
| --- | ---: | ---: | ---: | ---: |
| 修正规则 | 0.948 | 0.750 / 0.786 | 0.878 | 0.727 / 0.785 |
| 原完整神经网络 | 0.708 | 0.455 / 1.000 | 0.670 | 0.455 / 1.000 |
| 服务正类加权 | 0.712 | 0.739 / 0.812 | 0.677 | 0.778 / 0.761 |
| 加权并校准 | 0.712 | 0.739 / 0.812 | 0.677 | 0.778 / 0.761 |
| 三步辅助，固定阈值 0.50（补充诊断） | 0.711 | 0.659 / 0.841 | 0.686 | 0.739 / 0.839 |
| 三步辅助并校准 | 0.708 | 0.500 / 0.946 | 0.680 | 0.551 / 0.980 |
| 同一三步服务头 + 规则运动 | 0.945 | 0.500 / 0.946 | 0.878 | 0.551 / 0.980 |

加权使召回率相对本轮重新训练的原网络明显提高，但精确率下降；加权模型的校准阈值仍为 0.50，所以预测和决策没有变化。探索性补充显示，固定阈值 0.50 时加入三步辅助后，Tartu / clinic 召回从 0.739 / 0.778 降为 0.659 / 0.739，精确率从 0.812 / 0.761 提高到 0.841 / 0.839；5 步联合正确率在 Tartu 不变（0.520），clinic 从 0.357 升为 0.379。对同一三步权重将阈值从 0.50 调整到验证集选出的 0.60 后，召回进一步下降、精确率提高，如表所示，闭环流转未变。该补充发生在查看首轮总表后，不重新训练或以测试集选阈值；首轮结果也[原样保留](../examples/evidence/service-dynamics-20261109/initial-evaluation-summary.json.gz)。

与修正规则对同一服务机会配对：加权头在规则错误时正确 32 次，规则在加权头错误时正确 27 次；两地图加权服务 F1 分别为 0.774、0.770，规则为 0.767、0.755。它们说明预测包含**可能互补的局部信息**，但差距很小；这些机会来自同一批场景，只有 4 个独立布局/种子簇，不能据此证明可靠优势。三步目标是当前状态下、站点继续可用时的 3 步完成事件辅助损失，**不是**对完整机器人系统进行三步反向传播。

3/5 步条件预测每个 episode 从符合条件窗口按时间每 5 个取 1 个，各模型使用相同窗口。Tartu 分别评估 732 / 690 个窗口，clinic 312 / 269 个；筛选排除未来新分配、新任务和站点变化，因此不能把它解释为跨故障事件的预测表现。下表的误差是 `1 − 已知实体联合正确率`，越低越好：

| 模型 | Tartu 3 步 / 5 步误差 | clinic 3 步 / 5 步误差 |
| --- | ---: | ---: |
| 修正规则 | 8.20% / 10.29% | 24.36% / 34.57% |
| 原完整神经网络 | 39.48% / 47.25% | 52.88% / 68.40% |
| 正类加权（校准后相同） | 39.62% / 47.97% | 51.28% / 64.31% |
| 三步辅助、阈值 0.50（补充诊断） | 40.03% / 47.97% | 51.28% / 62.08% |
| 三步辅助、验证阈值 0.60 | 39.34% / 46.52% | 51.28% / 63.57% |
| 同一三步服务头 + 规则运动 | 9.43% / 12.03% | 24.36% / 33.09% |

完整一步、3/5 步联合及机器人、任务状态指标见 [prediction-metrics.csv](../examples/evidence/service-dynamics-20261109/prediction-metrics.csv) 和[逐 episode 记录](../examples/evidence/service-dynamics-20261109/prediction-cases.json.gz)。

## 配对调度闭环

四个测试布局/种子组合各含四种固定场景，共 16 个闭环配置；每种策略都用相同外生任务、故障、服务随机抽样规则、候选上限 8、3 步预算和原 `RolloutPolicy` 评分。不同策略执行后状态可能不同；相同状态的候选动作另有独立对照。每种策略全部 16/16 场景完成 6/6 样本，0 次离散安全违规、0 次回退。

| 配置 | 平均任务流转（仿真步） | 每次调度 CPU 时间（ms） | 对规则胜 / 负 / 平 |
| --- | ---: | ---: | ---: |
| 纯修正规则 | 99.448 | 0.799 | — |
| 原完整神经模型 | 99.917 | 2.279 | 2 / 5 / 9 |
| 正类加权 | 100.104 | 2.277 | 2 / 5 / 9 |
| 加权并校准 | 100.104 | 2.167 | 2 / 5 / 9 |
| 三步辅助，固定阈值 0.50（补充诊断） | 99.917 | 2.180 | 2 / 5 / 9 |
| 三步辅助并校准 | 99.917 | 2.223 | 2 / 5 / 9 |
| 同一三步服务头 + 规则运动 | 99.448 | 2.721 | 0 / 0 / 16 |

时延是本机单线程进程 CPU 时间，不是 GPU 设备延迟；短运行时计时有波动。混合实现为保持现有模型和规则语义，分别计算规则运动与神经服务，尚未针对速度优化。训练与评价发生在 PyTorch 2.5.1+cpu、Python 3.12；当前执行环境无 A100，因此没有使用 GPU 或开启付费资源。

同一事实状态的 39 个决策点中有 127 个候选评估；规则运动加神经服务与纯规则的候选评分和最终选择全部相同。原完整神经模型在 5 个决策点选择不同，候选评分差异对应运动预测；仅在本批预设状态下，候选任务的预测状态没有差别。现有评分只看候选任务的完成状态和几何距离，未直接计入其他任务积压和服务等待，且 horizon 为 3；这为“服务预测信息未转化为调度收益”提供了直接证据，而不是单纯凭最终均值推测。各模式和每个决策保存在[闭环汇总](../examples/evidence/service-dynamics-20261109/closed-loop-metrics.csv)、[同状态记录](../examples/evidence/service-dynamics-20261109/same-state-redacted.json.gz)。

## 判断与下一步

1. **预测信息：有小幅互补迹象，尚无稳健优势。**加权显著改变召回/精确的取舍，但相对强规则的 F1 差距很小，只有 4 个独立布局/种子组合。
2. **调度收益：本轮没有。**加权没有降低平均流转，预先指定的混合模型与规则逐例相同；不能据此排除其他评分或场景的价值。
3. **瓶颈证据：**PR #8 故障曝光不足在数据上得到修复；本轮原神经网络的联合误差仍主要由移动预测拖累，规则运动明显改善联合准确。更关键的是，混合方法对 127 个候选给出与规则相同的分数，指向本轮评分和视野未吸收服务信息。数据规模与仿真假设仍限制外推；现有证据不足以单独归咎模型表达能力。
4. **暂不需要 GNN/Transformer。**下一步应先在验证集设计并冻结能利用已知服务进度、等待和积压的候选评分或价值目标，保留原评分与强规则对照，再使用新的独立测试种子检验；补充故障持续时间与设备观测差异、增加场景簇。只有在信息能改变合理决策而集合模型仍持续无法建模关系时，再做关系特征或小 GNN 消融。

