# PR43：世界模型未来状态信息到调度效用的迁移验证

## 起点与研究问题

PR42 对已用过的 8 个 PR30 开发场景实际诊断：V4 数值编码的完全碰撞 0/8；完整 H20 多字段状态摘要打平 0/8；但在 shift 有 2/8 的 H20 预计完成工序数打平。说明应当先审查 **预测分布 → 调度动作评分** 的信息利用，不能直接宣称 Deep Sets 无法表示动作关系或立即改造 GNN。

**研究问题：** 若冻结同一个 V4 世界模型，是否能通过复用已有的轨迹级状态代价，改善完整在线调度，尤其是跨服务参数 shift 的迁移？

## 方法迁移，不另造算法

- Chua et al., *Deep Reinforcement Learning in a Handful of Trials using Probabilistic Dynamics Models* (NeurIPS 2018), [论文](https://proceedings.neurips.cc/paper/2018/hash/3de568f8597b94bda53149c7d7f5958c-Abstract.html)：概率模型粒子传播与估计期望轨迹代价。这里仅复用粒子评分思想，不宣称复现 PETS 的学习集合、CEM 或控制结果。
- 仓库 PR27 已有的 `experiments/world_model_integration/decision_value/pr27_evaluate.py::_trace_cost`：在预测粒子上累计未完成任务随时间的代价、逾期加权，并在 H20 末端计算剩余行程。**直接调用该函数，权重、目标和实现不变**。
- 仓库 PR30 原有 `OnlineHorizonPolicy`：冻结 V4、H20/P3、最多4个合法CP-SAT候选、预测状态上CP-SAT续调度、CPU进程时间超预算回退到合法首候选。

## 首次实验前冻结的四个在线臂

| 臂 | 唯一变化 |
|---|---|
| CP-SAT | 原始 CP-SAT 首合法提案 |
| V4-completed | PR30 原 H20 预计完成工序数最大化 |
| V4-tie-trajectory | 保持上述完成工序数为第一目标，**仅当完成数打平**，再按 PR27 原轨迹代价、末端剩余距离排序 |
| V4-trajectory | 将 PR27 原有轨迹代价作为第一目标，以末端距离破平局 |

所有臂都通过同一 `BusinessSimulator` 实际执行从开始到终局的完整在线重调度。后续预测的工作流动作只基于**预测状态**，不能读取事实未来。

## 独立场景与评估

`pr43_protocol.json` 在首次评估前固定 24 个此前 PR30 未使用的新种子，light/medium/heavy/shift 各 6。保留相同业务参数结构；比较各策略的真实完成 tick、逾期任务、容量等待、受阻移动、胜平负、改派次数、预算回退、CPU 开销、安全违规。此 24 组是独立于 PR42 的**新合成在线评估**，不是跨地图泛化、企业设备遥测或统计定论。

不根据 PR42 shift 的两组结果调权重。PR27 中的未完成每 tick 代价和逾期权重严格保留，模型、训练数据、评估随机种子和已归档历史全部不修改。

### 必须避免的错误解释

- PR42 “完成数打平但未来状态不同”不意味着某一额外指标一定能改善真实完成时间。
- V4-trajectory 若有提升，只能证明既有状态预测在新的效用读出下被利用；不证明神经世界模型本体预测更准确。
- 若 Rule-H20 之类规则基线收益相近，不能归功于 V4 的学习型动态。
- 受 0.5 秒 **CPU process time** 限制；模型单次 rollout 无法被真正抢占，过界后回退不代表硬 wall-clock SLA。
- 各臂随真实在线决策偏移会产生不同后续状态，因此逐时刻调用次数不可直接解释为完全相同输入上的打分对照。
- 实验只用现有合成环境，并不预示现实设备故障预测可用。

## 已执行：独立24场景完整在线复核

原冻结场景与四组实验由一次工作流实际执行：[Actions #43153515015](https://github.com/lieuyimo/wm/actions/runs/43153515015) **SUCCESS**；[逐场景及逐决策原始Artifact #13914787519](https://github.com/lieuyimo/wm/actions/runs/43153515015/artifacts/13914787519)。

环境按 PR31 恢复冻结 V4，原权重 SHA256 成功校验，单元测试 6/6 通过，**24 场景×4 臂=96 条完整真实在线轨迹、0 GPU、0 新训练、0 安全违规**；实验累计 97.69 CPU-process 秒。

### 实际均值：场景内每臂6个不同seed

| 场景 | CP-SAT | 原 V4 完成数 | 完成数优先/轨迹破平局 | 轨迹代价优先 |
|---|---:|---:|---:|---:|
| light | 20.000 | 20.000 | 20.000 | 20.000 |
| medium | 50.000 | **47.667** | **47.667** | **47.667** |
| heavy | 71.667 | **71.167** | 71.833 | 72.167 |
| shift | 108.000 | **107.500** | 108.667 | 107.667 |

对原 V4 完成数读出：
- 轨迹破平局：light 0胜6平0负、medium 0胜6平0负、heavy 0胜4平2负（平均+0.667 tick）、shift 0胜4平2负（平均+1.167 tick）。
- 全轨迹代价优先：light 0胜6平0负、medium 0胜6平0负、heavy 1胜1平4负（平均+1.000 tick）、shift 1胜4平1负（平均+0.167 tick）。
- 逾期：light/medium 所有臂均无逾期；heavy 原V4平均2.167，两个轨迹臂平均2.000；shift 原V4与两个轨迹臂均平均3.500。不同指标之间存在取舍，不能只选一项报好看数字。
- CPU预算：heavy 原V4 7次超CPU进程时间预算并回退，破平局9次，全轨迹7次；shift 三个V4臂均0次预算超限。这些是逐决策计数，不是6个episode中的失败数。
- 破平局实际改变了与原完成数策略相对的候选：heavy 2次，shift 4次；**更频繁改选并未转化为完成时间收益**。注意策略逐时刻随真实状态分叉，不能把所有后续决定当成共同状态下的对照。

### 方法判断

**本次不支持将旧 PR27 轨迹代价替代原 V4 完成数调度目标；不晋升新方案。** 完整未来状态中有差异，本身不保证决策收益。PR42 的结构性碰撞未在8个实际候选对上观察到；PR43 的新在线样本则说明仅调整效用读出不够。

这也不能推出世界模型其他动态（设备风险、故障恢复、工作站资源等待）无价值。当前 V4 仍只学习服务完成局部事件。下一阶段更应从可观察站点健康条件下的**未来系统状态演化**入手，明确在当前观察可用的什么条件下，额外健康/任务关系动态可以被学习并改变决策。

后续会对 PR43 已保存的完整逐决策记录做**严格只读**的首次偏离原因审计，区分客观评分变化、CPU回退、候选集合变化，无新仿真、无新模型调用。不能在本次独立24场景上重新调权重再声称新的独立改善。


## 追加只读归因：首次在线派单分歧

使用源在线结果 [Artifact #13914787519](https://github.com/lieuyimo/wm/actions/runs/43153515015/artifacts/13914787519) 作**只读**输入；复核 SHA256 和原始源 commit， [Actions #43154060297](https://github.com/lieuyimo/wm/actions/runs/43154060297) SUCCESS，4 项只读审计测试通过，[完整首次分歧报告 Artifact #13914892417](https://github.com/lieuyimo/wm/actions/runs/43154060297/artifacts/13914892417)。

本轮 **0 新轨迹、0 模型推理、0 GPU、0 新训练**。逐场景对齐原 V4-completed 和新在线策略在各自**动作历史尚未分叉之前**的首次不同选项；第一次分歧后的状态不能再当作相同状态作逐tick比较。

| 策略 | 场景 | 首次动作分歧的场景数 | 同候选集合下分歧 | 首次分歧发生在完成数打平 | 首次分歧时 H20 状态摘要不同 |
|---|---|---:|---:|---:|---:|
| 破平局 | light / medium | 0 / 0 | 0 / 0 | 0 / 0 | 0 / 0 |
| 破平局 | heavy | 2/6 | 2 | 2 | 2 |
| 破平局 | shift | 3/6（均tick0） | 3 | 3 | 3 |
| 全轨迹 | heavy | 5/6 | 5 | 5 | 5 |
| 全轨迹 | shift | 3/6（均tick0） | 3 | 3 | 3 |

- **关键归因：** 不是候选生成器变化导致第一个决策分歧。两种新目标在所有首次分歧上，原完成数预测都打平，完整预测摘要却存在差异。说明这次迁移确实“使用了额外预测信息”。
- **独立结果：** 额外信息在这24组新场景中**没有提高真实完成效率**。破平局在 heavy 0胜4平2负、shift 0胜4平2负；全轨迹在 heavy 1胜1平4负、shift 1胜4平1负。当前 PR27 轨迹代价作为读出方法不予晋升。
- **CPU 区分：** shift 所有 V4 方法预算超限为0，因此其完成时间劣化**并非超时回退造成**。heavy 破平局比原 V4 多2次预算超限，不能将所有 heavy 差距纯归因于评分函数；但首次动作分歧证据定位在真实打平的同候选状态上。
- **观察局限：** 本分析仅说明被验证的固定 PR27 成本函数没有新增在线收益。不能声称任何利用丰富状态的决策目标都无效；也不能据此断言 V4 本体的关系预测完全充分。

### 下一研究方向

**PR43 裁决：轨迹效用迁移 NO-GO。** 不在这24个新seed上优化调度权重或再次称“独立验证”。保留现有原 V4-H20 为实验参考方案。

现有模型仍未学习站点健康的未来演化。应重新优先研究「在真实可见健康/告警/时间上下文条件下，世界模型能否预测未来工作站可用性、故障恢复与资源等待，并使预测增量进入合法系统状态转移」。第一步是观测信号与可学习性验证，必须排除合成 outage 真值 oracle，不直接从本轮调度评分损失推断 GNN 需求。
