这个单场景中，两种学习模型的平均流转均慢于规则和最近优先，不能声称学习模型改善调度。测量时间受机器负载、Python 记录、求解与原生进程调度影响，单次结果不是实时性保证，也不能与 PR #15 未记录完整候选预测的旧耗时直接相减。

## 事实轨迹上的业务联合预测

三种模型对**同一条最近优先事实轨迹**的同一组选中窗口做独立离线预测；窗口覆盖、具体选中时刻及各模型结果保存在 `comparison.json`。不能把三种闭环的不同事实状态混成同一分母。

| 模型 | 1 步 | 3 步 | 5 步 |
|---|---:|---:|---:|
| 规则 | 12/15 | 6/11 | 2/7 |
| PETS | 15/15 | 4/11 | 0/7 |
| 结构化服务头 | 14/15 | 2/11 | 0/7 |

这里“一致”要求业务任务身份和状态、机器人位置/任务及站点关系同时正确；窗口会重叠且排除了未知到达、设备状态改变等情况。样本很少，PETS 一步 15/15 并不代表整体优于规则，更不代表五步或调度有收益。更大范围的既有确认结果以[PR #15 报告](workflow-prediction-results.md)为准。
