# PR #17：世界模型可观测信息与故障预测价值审计

## 证据范围与边界

只读取 PR #16 的 24 个确认场景、8 个地图/种子簇、48 个决策、174 个原始 CP-SAT 候选，以及原有 25 个额外服务随机性状态。
不训练、不重放、不生成新实验。未来真实状态仅用于事后标注。完全相同的故障发生/恢复时刻在所有候选间一致的检验结果：通过。

## 在线信息 A、公开规则 B 与未知未来 C

**A：当前可见。** 机器人位置、任务/阶段/服务进行状态，工作站 device_available、资源容量占用、capacity_blocked、当前 tick 与已公开的工作流状态。当前设备可用性必须读取 device_available，不能用受资源满载影响的 available 替代。状态文件实际字段名见机器可读 summary。

**B：公开确定。** 地图/工作站位置、资源容量及分组、工作流的多阶段路径和已经公开的任务元数据。公开工作流模板不代表能知道未来外部任务的到达时刻。

**C：事后才知道。** 未发生的设备故障和恢复、真实服务持续时间、尚未公开的外部任务；不得从 case assumptions、后台故障日程、trace_first20 或反事实结果提取在线预测特征。

事件口径：对每个决策的当前站点状态与每条原始候选后续 20 个连续真实状态比较，仅 device_available 从 true 转为 false 才计作新故障；已经不可用的设备单列。记录故障绝对 tick 与距离决策的 offset。分别按 5 和 20 步窗口分组；故障场景名称不是状态标签。

48 个状态中，决策时已有设备不可用 0 个；未来 5 步内新发生故障 0 个，未来 20 步内新发生故障 8 个。
这 8 个真实故障前决策均发生在 tick=0，故障在 tick=10 开始（距离决策 10 步）。

## 事后机会由哪些真实事件贡献

按实际故障跃迁而不是场景标签分层，20 步内将发生故障的 8 个状态贡献了 87.59% 的 Rule-5 到 Perfect-State-20 总损失下降。这个贡献说明事后未来故障信息对候选排序影响大，绝不能把该百分比解读为可提前预测的模型收益。
这些状态在原 PR #16 三个额外未来服务扰动种子的稳健性记录中覆盖 8 个，事后最优候选保持最优 8 个；条件子集的平均可得机会为 6.6111 步。该稳健性仅改变后续服务随机数，不改变外生故障日程；因此既不验证故障预测能力，也不代表全 48 个状态的随机重复均值。

## 能否从现有在线信息预测未来设备故障？

**故障发生前的设备状态变化：** 当前观察字段只有设备可用/不可用状态，没有预设的健康分数、错误码、预警事件或故障概率。未来状态中出现的设备状态跃迁，只能在其真正发生时被识别，不能回填到之前的决策时刻。

**服务历史与进度：** 当前机器人可见 service_elapsed、service_active_elapsed和 service_paused_elapsed；工作站还暴露 observed_effective_service_count、observed_effective_service_mean、history_complete_since_start 与 expected_service_ticks。这些是历史服务统计/预期，**并非设备健康预警**。顶层含 history/event/log 字样的字段：无。
8 个真正发生未来故障的决策均位于 tick=0，此时服务历史计数、活动服务机器人、资源占用全为 0，不能从已有服务历史推断十步后的设备故障。
当前状态中的服务历史统计可以帮助分析一般服务时间，但现有材料没有设备健康退化与未来故障的标注对应关系，不能由服务时间变长直接推定未来故障。

**资源占用与负载：** resource_occupied 和 capacity_blocked表征当下调度/队列拥堵，与未来设备故障预兆不是同一变量。8 个故障前 tick=0 的状态资源占用全部为 0。即便有限样本出现相关性，也可能来自固定场景/时刻配置，不能称为可部署的故障风险模型证据。

**故障来源与信息泄漏：** PR #16 记录的是仿真中外部故障日程触发的真实状态，未发生事件对线上规则与模型不公开。Perfect-State-20 直接使用已经实现的未来，因此其优势不能等价为当前观测可推断的未来。不能把后台 outage 时间表、未来服务随机数或事后标签当成学习特征。

样本只有 8 个独立地图/种子簇，按同一种子配对的三个业务场景不是独立故障史；既没有真实设备随时间退化数据，也没有观测-故障的前瞻性验证。因此本轮不计算伪造的故障分类准确率、AUC 或置信风险分数。

## 最终裁决：B（没有足够可观测的提前预警信号）

现有世界模型能够依据当前设备是否已经不可用、服务是否正在进行、资源是否拥堵等已发生事实调整调度，但**不能凭已有观测可靠地提前判断尚未发生的外生设备故障**。服务时长及后续任务的不确定性同样不能从事后 Oracle 优势直接倒推为在线可预测。

若需要在真实实验室建立可验证的预警任务，最小新增数据应有：设备 ID、带时间戳的可用/故障/恢复状态切换与错误码；设备运行时长、维护与告警记录；工位开始/结束服务的样本/设备/时间戳；当前队列长度、资源占用、任务到达时间及公开时刻；以及明确区分事件产生时间与调度器实际接收时间的日志。有条件再采集设备特定健康遥测（温度、电流、振动等），需按设备故障机理选择，不能虚构为现有可用字段。训练/验证须按时间和设备分组，并与只依靠设备当前状态的基线比较。

**下一阶段：停止继续训练现有世界模型，不启动 PR #18，不修改故障情景，不重跑实验；只保留本次只读审计与数据需求。**
