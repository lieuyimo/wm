# PR35：H20 在线世界模型的最终候选预算门禁修复与独立验证

日期：2026-11-12

## 正式结果

**修复已通过。** 之前 PR33 的只读审计发现：原 `OnlineHorizonPolicy.__call__` 只在预测每个候选之前比较 `time.process_time()-start >= 0.5`，遗漏了**最后一套候选计算完成后的验收**。因此此前 PR30/PR32 虽进行了真实在线仿真，却可能在超过 0.5 秒进程CPU预算后仍采纳模型重排，不符合预期的有限预算决策采纳语义。

本 PR 仅修改同一原策略的预算门禁，不改业务事件机制、模型结构、评分、CP-SAT候选集合或真实机器人运动与工作流约束。对单次不可抢占的模型/续调度调用，采用**每个候选开始前 + 完成后 + 排序采纳前 + 最终记录时**的 CPU 复核；超限立即退回合法的原 CP-SAT 第一候选，保留超时和回退记录。**不能承诺单次调用响应延迟必定小于0.5秒**，只能承诺从模型评分选择的**非首选派单动作不会在本次观测到CPU超限时被采用**。

## 可复现实验

- 新场景：`experiments/world_model_integration/strict_budget/pr35_protocol.json` 在跑正式新场景前冻结 24 个全新 seed，每组6个 light、medium、heavy、shift，互不重复，且不与 PR21～PR34 的开发、测试、训练/验证分组混用。
- 四臂：CP-SAT、Rule-H20、原冻结 V4-H20、PR31 Validation 提前选定的 scratch V4-H20；原始V4及新V4权重全程只读、SHA256 校验。
- 共同条件：真实 BusinessSimulator，合法 BusinessCPSAT 每次最多4候选，H20/P3，当前公开状态，原 keyed service duration，0.5秒**进程CPU决策采纳限制**，后续自动在线重规划；无新训练、无GPU。
- 专门的人工进程CPU时钟回归：第一候选预测刚结束就超限、**最后一候选预测超限**、恰好0.5s边界、预算内合法改选、独立场景种子不重合。5项测试通过。
- 24×4完整场景实际执行后再次直接审计每个 `decision_records[].selected_index`、`process_cpu_seconds`、`budget_exceeded` 与 `fallback`。禁止任何已观测到超预算却采纳非首选方案的记录。
- 限制：CPU数据源自GitHub Actions runner，属于进程CPU时间而非事件时钟或墙钟延迟；无法暂停正在执行的OR-Tools求解或模型粒子循环，因此预测计算本身可能持续超过门槛。

## 裁决和下一阶段

1. **有限预算动作采纳语义：PASS。** 人工时钟与新独立在线24组实验双重验收成功。
2. **模型辅助调度业务价值：条件正信号。** 在本批medium/heavy新场景，原V4-H20相对CP-SAT的真实makespan有改善；在所有场景和seed上并非全胜，尚不足以证明现场生产级稳定性。
3. **后训练带来的额外调度收益：本轮未发现。** Scratch相对原V4在medium完全持平、heavy总体同均值但逐场景不稳定、shift略逊，PR31独立事件Brier降低不应被写作终局调度收益。
4. **部署延迟门槛：未满足。** 超限后回退的动作采纳安全已经实现，但不可中断预测仍可能拖过单次0.5秒；下一轮先研究已有 `nearest_batch` 续预测策略或有来源的缓存加速，再对独立场景验证真实CPU时延与makespan。此项优先级高于继续追加训练轮次。
5. 保留 PR31 的完整可恢复训练环境、原始/最佳与最新optimizer及RNG断点、源SHA、pip锁文件和数据快照在 [Draft Release](https://github.com/lieuyimo/wm/releases/tag/untagged-871b60f7bf013400cb45)，不覆盖原V4权重、PR30～PR35任何已归档事实。

原 CP-SAT/Rule/V4 的真实业务规则和训练历史均未修改；本 PR 保持 Draft 不自动上线。
