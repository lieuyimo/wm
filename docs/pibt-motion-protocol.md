## PIBT 接口与信息边界

[C++ 薄适配器](../native/pibt_bridge/pibt_bridge.cpp)构造上游 `Graph` 和 `MAPF_Instance`，通过上游公共 `setDistanceTable` 提供由现有 `Geometry` 计算的真实当前图距离，实际调用作者实现的 `PIBT::solve` / `PIBT::run` / `PIBT::funcPIBT`。这没有改写优先级继承或回溯算法。上游内置网格读入默认双向；适配器显式传递原拓扑的每条有向边，不添加反向边。输入只包括当前可观察任务目标、位置、服务锁定、暂停状态和静态拓扑。

服务中、等待服务或当前暂停的机器人作为动态障碍保留其格点；其他机器人不能进入。目标当前被锁定或从剩余图不可达时，该机器人暂以当前位置作为本步目标并记录原因；不虚构故障结束时间。输出独立校验节点、合法边、顶点冲突、交换边和锁定位置。空闲机器人可被 PIBT 临时让行；旧后端通常停在其目标，这属于运动协调语义差异，调度输入和任务分配策略保持一致。

上游 PIBT 没有公开单步状态接口；为满足动态服务及状态变更，本适配器每个仿真步调用一次官方求解器并取第一步，因此**每步重置上游私有优先级年龄**。这是有局限的滚动调用，不声称等价于论文中的连续 PIBT，也不继承其活性保证。特别是有向图、桥边和动态锁定资源未必满足原定理条件：即使实验完成，也只能称此设置下实际完成，不能证明其他起点可达。

`PIBTMovementModel` 使用同一个无状态运动适配器和固定策略随机种子组合现有服务预测；本步执行与预测都锁定当前服务和可观察暂停，使用同一目标/位置/图及同一运动种子。未知未来暂停/故障变化不被确定性注入，故跨这些未来变化的多步预测不能宣称精确。路径预测不再沿用旧后端来冒充 PIBT。实际仿真与推演分别持有各自适配器实例，状态/种子相同才可比较。

## 冻结对照

[配置](../experiments/pibt_motion/benchmark_config.json)固定了全部 PR #12 的 16 个独立确认场景、两张同源公开 MAPF 地图的 3 机器人回归及 4 个新增 5 机器人场景。额外机器人的初始位置和家点是明确写出的仿真假设。两组使用相同最近优先调度、任务、释放、站点资源和按任务键固定的外生服务扰动；候选任务分配逻辑不由上游 MAPD 接管。所有正常/异常、完成/未完成场景均保留。阶段单元另行比较 CP-SAT 和现有三种服务模型在执行、预测中调用相同 PIBT 原生运动接口。

主要指标是各场景业务任务及阶段完成数、包含所有任务的完成率、已完成样本流转及运行上限截断的受限平均流转、最长无机器人移动时间、顶点/边交换/非法边、设备与容量等待，以及每次运动规划的墙钟均值/P95。无机器人移动也可能是正常服务，不能自动判成死锁。旧规划器拒绝动作的尝试次数与 PIBT 内部冲突尝试不等价；后者上游接口不暴露，记为不可用，不记成零。
