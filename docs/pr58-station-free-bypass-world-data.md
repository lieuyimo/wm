# PR58：有绕行路径的公开拓扑世界模型数据试验

## 研究问题与原则

本阶段的第一优先级是**学习真实系统动态的高质量数据**，不是使调度器得分漂亮或把已有真实数据简单复制更多份。

原[PR57 Draft](https://github.com/lieuyimo/wm/pull/57) 在原始7×5网格的四种障碍布局下构造了12组真实BusinessSimulator开发场景，有2,102条真实逐tick公开状态转移、16次设备故障和16次恢复；但**仅7/12真实场景完成，5/12在260tick上限下右截尾**。原4幅地图均存在一个静态图割点，工作站C位于该割点；但`south_wall`全部完成，因此**仅凭割点无法证明超时的具体因果来源**。原始5组超时轨迹均保留，不得删除、改成completed或当作真实260tick makespan标签。

本PR不直接增加200或240个随机场景，而是检验控制变量的研究问题：

> **当其它真实业务条件全部相同，仅改变公开可见的通行拓扑，原CP-SAT/BusinessSimulator是否可以在保留设备故障、任务动态与H20合法动作差异的同时，产生完整可用的业务标签？**

相邻工作方法参照：
- [Multi-Agent Pathfinding: Definitions, Variants, and Benchmarks (SoCS 2019)](https://www.movingai.com/benchmarks/mapf.html)：公开MAPF基准区分开放、随机障碍、房间、迷宫和仓储地图等类型，而不是单地图无限增加随机seed。
- [MAPF Benchmarks（Pathfinding AI）](https://benchmarks.pathfinding.ai/mapf-benchmarks/)：社区独立划分城市、随机、仓储等环境域，可借鉴`地图拓扑家族`作为模型泛化实验单元。
- [MAPF in 3D Warehouses: Dataset and Analysis (ICAPS 2024)](https://ojs.aaai.org/index.php/ICAPS/article/view/31525)：地图结构可能实质影响多机器人路径规划难度与速度；本项目的单层实验地图**不是**该文的3D仓储设置，不声称复现其结果。

## 实验设计：12组旧场景逐一配对、仅改变地图

新源代码：`experiments/world_model_integration/bypass_pr58/`，新增文件：

- `protocol.json`：预先固定4种无静态割点的**可绕行布局**和12组原PR57案例的映射；原每个业务案例的`seed`、故障工作站、故障长短机制、任务数量、释放节奏、机器人及资源站点配置原样保持，**12个新场景对应12个旧场景**。原5组截尾案例都在对照名单内。
- `pr58_run.py`：严格检查生成的新旧`business.jobs`、`business.rules`、`business.scenario.stations`（包含真实私有故障表）、`business.scenario.robots`和时限相同，唯一变化是`Grid.blocked`。在使用完全相同的原`Grid`、`Geometry`计算动态时，**直接复用PR56已有`run_scene`，没有重新实现物理仿真器或调度评分器**。
- `pr58_gate.py`：读回历史PR57真实原始分支数据与新PR58结果，逐个验证源SHA、相同事实场景、完整原始逐tick公开输入及下一时刻标签、真实同历史合法动作的H5/H20差异；原本缺失的makespan严格标记为右截尾。
- `test_pr58.py`：验证4种拓扑全部没有静态割点、站点之间的地形绕行真实存在、所有12对只改变地图、原始原地图未被修改、新数据不是独立TEST、0 GPU。
- `.github/workflows/pr58-station-free-bypass-quality.yml`：三个完整CPU矩阵生成真实场景；汇总工作读取原[PR57 SOURCE RUN #43219314493](https://github.com/lieuyimo/wm/actions/runs/43219314493)的原始3个source Artifact以及原来的**NO-GO质检**，全部逐文件SHA256验证，然后进行原12 vs 新12逐场景配对质量审计。

四个新地图的受控拓扑方案均仍保留原来的7×5尺寸、5个工作站位置、3台机器人、相同业务流程，不改变底层行走、站点资源和CP-SAT算法。布置为：

| 新地图 | 被替换的原开发地图 | 有意设计的通行结构 | 静态割点 |
|---|---|---|---:|
| `west_detour` | north_wall | 左侧中间障碍带，顶部及底部绕行 | 0 |
| `east_detour` | south_wall | 右侧中间障碍带，顶部及底部绕行 | 0 |
| `alternating_islands` | central_bottleneck | 双侧交错障碍，保留多条绕行通道 | 0 |

所有地图从**实际公开的可通行网格与连接边**生成PyG map-sidecar，且地图位置及站点最短路发生实际变化；未来设备恢复时间、未公开任务到达表等隐私变量不输入世界模型。**旧PR54神经模型目前尚未学习这些双图特征。**

## 质量验收先于实际仿真被冻结

`protocol.json`从实验开始就规定：

- 12个完整真实trace、12个原对应trace和相同真实业务环境种子必须保留；
- 4个不同新地图全部连通、没有任何静态割点，站点间绕行路程真正与无障碍地图不同；安全/因果违规为零；
- **至少10/12新事实episode完整完成、至少挽救3个原截尾案例、不能使任何原已完成案例退步**；
- 真实设备故障/恢复各≥12次，保留第56步之后真实动态事件≥12条；
- 至少10组有多个合法同一公开历史候选与H20实体状态差；至少9组所有真实候选分支完整完成；至少6组产生**完工时间完整可标注**的合法动作差异；
- 没有未来私有状态进入模型输入，0 GPU、0神经模型训练；通过也只允许规划新的独立数据协议，而不是宣称已验证模型泛化或直接生成240场景。

任何一项不满足，输出`NO_GO_BULK_DATA_EXPANSION`并保留所有事实。**不能仅仅因为场景在截止tick结束就用这个时间当作真实成功标签。**

## 学术解释与明确边界

这轮只证明：**在同一仿真业务配置、相同可观察动作规则及4幅可通行结构不同的新开发地图上，可以获得更完整、动作敏感且可复现的真实状态预测监督数据。**

不能宣称：
- “删除静态割点是机器人超时的唯一因果机制”。更换障碍会改变可行路线和之后的机器人/服务序列，甚至改变随机数抽样调用顺序；这是一组受控模拟配对，不是所有外生随机结果完全固定的严格因果实验。
- “新世界模型在新地图上泛化提高”。**尚未训练任何使用双图地图的神经世界模型**。
- “已有独立OOD TEST”。全部24个新旧场景均是用于方法和质量开发的已观察场景；这批12个原seed本身也不是独立新测试。
- “绝不会发生真实机器人的死锁”。只检查既有离散业务仿真、源场景的合法工序和资源约束，未接入企业真实地图及机器人控制。

## 下一步的高质量数据扩展方案

**先冻结真正独立的地图家族和随机种子，再开始下一批CPU数据，不需要GPU。**

1. 构造互不重叠的地图族：训练集含不同绕行冗余、工作站服务附近拥堵和可达瓶颈；验证地图完全与训练地图不同；真正的OOD TEST还要有**训练时未使用过的拓扑家族**（如更大网格、非相同障碍模板、独立仓储/房间布局）。已开发的PR57/58八幅地图不得用于声称“独立新拓扑盲测”。允许静态可达性检查，但不允许在TEST仿真效果上调生成规则。
2. 地图拓扑输入合同必须进入真正学习模型，不能仅把新地图JSON保存出来却继续用不含障碍的旧模型。当前`topology_pyg_dual_graph`有实体图、map图、实体—cell链接；下一PR先验证多地图batch时两个ID命名空间和梯度传播正确，才训练。
3. 以**质量分层配额**而不是场景总量作为数据生成驱动力：工序状态变化、服务进展、已观测设备健康、故障恢复、资源容量与拥堵、动作H5/H20状态效应的大小和分布、不同拓扑绕行程度及完成/截尾率；记录每一种类别新增覆盖。不能只统计“有变化”的布尔值，需检查动作造成的未来状态差异幅度，防止微小但无实际意义的标签。
4. 先为TRAIN构造约60个全新独立真实场景，检查对前批数据的**边际信息增益**、重复率及概率校准所需的自然事件分布，只有有必要才扩至120乃至240。所有验证/TEST按自然完整真值数据分布评估，只有训练集允许针对t+1事件标签分层采样，保存无筛选raw并记录选择概率。
5. 对完整调度后果和真实H20动作排序的标签，所有候选分支都必须合法完成；对截尾情况保留真实一步状态、真实观测H5/H20有效部分及右截尾标记，**不伪造完成时间**。

**当前核准范围仅为下一阶段独立数据协议设计，不是允许GPU训练或直接批量采样240场景。** GPU完整世界模型训练仍按[Issue #54](https://github.com/lieuyimo/wm/issues/54)另行执行。
