# PR32：后训练 V4 的独立在线调度价值验证（2026-11-12）

## 研究结论

**训练与独立服务完成概率预测提升已成立；“后训练必然改善在线调度”的假设未通过本轮独立验证。**

本轮正式运行 24 个新合成场景 × 5 种真实在线策略，所有组均完成样本任务且满足现有资源/机器人运动/工序合法性审核。此前 PR31 中，热启动和从头训练都明显降低了新独立事件 Test 的 Brier；在本轮真正在线调度中，选择进入调度的 **scratch_v4_h20（仅按 PR31 Validation 最优提前选定）** 没有稳定改进，甚至在中负载和服务时间 shift 中相对原 V4 退化。

绝不将此次 Test 的比较结果反向用来更改模型选择、训练超参、任务种子或原始 CP-SAT 规则。

## 相邻方法与工程复用

- Chua et al. (NeurIPS 2018), **PETS**：参考已在 RHWM 中实施的 P=3 有界多粒子概率世界模型状态预测，不冒称已复现 PETS 完整连续动作 CEM 训练/优化器。
- Reijnen et al. (2026), **Job shop scheduling benchmark**：任务和资源负载分层研究设计，参考其公开 MIT 工程基准设定，不复制论文实例和特定策略。
- PyTorch 官方 Adam + BCEWithLogits：PR31 只用原有 V4 Deep Sets 结构、源训练方法与增量事实数据，保存恢复所需优化器与随机状态。没有提出新网络或损失。
- 真实调度严格复用 PR30 `OnlineHorizonPolicy` + `BusinessCPSAT` + `BusinessSimulator`，H20/P3、最多 4 候选、0.5秒进程CPU预算、超预算退回第一合法 CP-SAT 候选，改变的唯一参数是现有 V4 推理权重。

| 每组均值（完整场景 CPU 秒） | CP-SAT | 原 V4-H20 | Warm-H20 | Scratch-H20 |
|---|---:|---:|---:|---:|
| light | 0.025 | 0.214 | 0.206 | 0.215 |
| medium | 0.069 | 0.923 | 0.921 | 0.926 |
| heavy | 0.154 | 2.801 | 2.657 | 2.662 |
| shift | 0.165 | 2.534 | 2.449 | 2.503 |

中负载：Scratch 共 7 次改变 CP-SAT 首选方案，原 V4 8 次；Scratch 在真实终局没有给出更好的总体排序。
高负载：Scratch 5 次改变，原 V4 7 次。所有三个 V4-H20 方案在高负载中都有 5～6 次**单次决策超出 0.5s CPU 限制并回退**，这属于长时预测+每粒子 CP-SAT 续调度的部署约束。
服务参数变化：原 V4 4 次改变 CP-SAT 首选，Scratch/Warm 均 0 次。因此即使新模型的事件 Brier 已降低，**旧 V4 有时反而能提出最终更好的调度动作**，两者区别与业务目标和候选评分有关，并非简单训练步数不足。
轻负载各模型都 0 次改变，所有实际结果持平。

## 与 PR31 训练结果的直接对照

PR31 的**事件级新独立 Test** Brier：原 V4=0.067313、Warm=**0.049349**、Scratch=0.050490；Scratch 是**事先仅由 Validation Brier 选中**，其在此 Test 不是最优但模型选择未被改变。

PR32 的**全程在线真实业务**：Scratch 对比原 V4 未建立收益。学习问题与调度问题应区分为：

1. 原V4训练覆盖及服务事件预测不足已在事实数据扩充后实质改善；
2. 当前由预测的“在H20结束时预期完成工序总数”排序调度候选，不必然吻合关键任务最终结束时间及截止时间要求；
3. 长时域、CPU预算和候选生成器的复杂交互让学习模型改进不一定造成可用决策差异；
4. Rule-H20 在中负载、高负载也有改善，必须控制规划跨度后才能谈“可学习事件动态的独立增益”。

这些属于当前结果支持的研究诊断，不需要也不支持无止境增加训练轮次。

## 下一研究门槛

**冻结本批 PR32 全部场景，不再用它们调评分系数或模型权重。**

1. 对已归档的 PR32 真实在线日志**只读**，对比不同策略在每个时刻的真实候选集合、是否受预算回退、H20对动作的预期完成工序数排序是否造成“关键工作超时”风险；明确旧V4与Scratch排序分歧的具体来源。
2. 参考 PETS / model predictive control 的有限预算规划方法、以及 job-shop scheduling 的 makespan/critical-path 目标，选择**正式论文已有、可迁移、且符合当前业务状态**的候选评分方法。优先做规则/价值函数适配与时间预算管理，而不是新增自定义网络。
3. 只有预先定义并冻结新的独立在线场景组后，才能评价另一套规则目标是否带来稳定收益；保留 CP-SAT、Rule-H20、原 V4 与 Scratch 全部对照。
4. 如果证据指出特定服务状态仍预测不准，再按照 PR31 已保存的完整可恢复 CPU 环境和 Adam/RNG 快照执行新的训练。不得根据 PR32 Test 结果直接多训几轮并宣称得到新的盲测改善。
