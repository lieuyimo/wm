# LaCAM3 完整联合规划：固定验收协议

基于 PR #13 `29fc99a89927660612d3289ca25333bf29927cdf`，仅使用官方 `Kei18/lacam3` 源码 `1c3ecf8ade40298f16047544634e9c0c1cf3b93c`。不改上游核心、不训练模型、不改变任务规则或 CP-SAT 目标。完整方案调用作者的 `solve()`，适配器只负责图、观测、锁定、固定临时目标与结果检查。只接受每条边均有反向边的拓扑，Tartu 绝不无向化。

首先读取 PR #13 已归档的 clinic 轨迹：第 37 步最后一个阶段完成后，找到首次重复状态及其重复时刻，提取最后 100 步的三种典型联合位置和原后端最后阻塞状态。保留机器人任务、阶段、目标、释放时刻、服务/暂停及资源锁定。业务目标重复时优先选择正在运输样本的机器人；若多个同时运输，以当前阶段释放时刻、机器人 ID 依次确定；没有运输时按当前任务释放时刻、ID 选取。其他可移动机器人临时目标为当前格，服务/暂停机器人格点保持锁定；不改变业务目标。如果这些临时目标仍冲突、目标被锁定或无完整合法解，记录状态并停止后续集成。

每次完整求解固定 500 ms 总墙钟预算，采用官方可配置的 `FLG_STAR=false`（找到第一个完整方案即返回）、单线程、无优化器和固定随机种子 `20261109`；仍执行官方 `solve()` 完整联合搜索，不声称找到最优路径。子进程超时后终止，返回不可用而不是执行部分路径。以上设置在检查确认轨迹之前固定，不针对输出调整。

若五个冻结状态均求得完整且通过合法性检查的联合路径，才开始实现持久化缓存与混合触发。触发固定为：连续 16 步无已完成业务阶段，并且最近联合位置重复；正在正常进行服务不能单独触发。目标、任务阶段、资源锁定、设备状态、暂停或实际位置变化时核对缓存；安全检查失败、不支持图或超时均安全回退并记录。不因同一目标和锁定输入的连续失败反复求解。

对照使用原始、PR #13 无状态 PIBT、PIBT 加 LaCAM3 恢复三个后端；同一场景共享最近优先任务分配、站点资源、外生服务与故障。原 Tartu、clinic 及 PR #12 的 16 个三机器人和 PR #13 的 4 个五机器人场景均不可替换；Tartu 包含单向边，应明确标记 LaCAM3 不支持而保留 PIBT 回退。业务活性统计包括未完成任务、最后完成阶段和连续无阶段进展，不能以运动代替业务进展。

恢复状态作为不可变快照附于当前观测，包含最近位置、无阶段完成步数、当前完整规划的剩余路径、缓存条件和已尝试输入。每个预测分支接收独立快照，不能改动实际执行器；规划路径是当前计算出的计划，不是未来真实事件。单步事实状态对照、缓存连续多步对照和服务/目标/占位变化失效均单独记录。模型如果预测错服务完成，其快照可以与事实不同，不能据此声称完整世界状态准确。

首次小规模闭环发现 clinic 完成后，追加一项单独的**事后机制诊断**：保持同一触发规则和官方完整求解，但只执行求解结果的第一步、丢弃剩余缓存；同一目标和锁定状态仍不重复求解。该消融用于分析路径持续执行的作用，不是新的独立确认集，结果无论成功失败均保留。

首轮配对后检查到：原实现把“任务身份变化但实际目标和锁定不变”也当作允许重试，超出了本轮“仅新目标或锁定状态才重新规划”的限制。已将重试键收紧为机器人目标与锁定集合；缓存本身仍会在任务身份或阶段变化时失效。首轮原始结果已单独保留，未调整 16 步、500 ms 或场景。另在模型接口验证中发现被容量阻拦的服务可能在内部临时表示为已开始，已在计算恢复缓存上下文之前清除该中间假状态，初次错误日志及修复测试均保留。
