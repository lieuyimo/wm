# PR #37：修复候选预测末端超时门禁与独立在线 H20 复测

日期：2026-11-12

## 结果裁决

**代码缺陷已修复，预算后采用非首选方案的违例次数为0。** PR33 确认原在线策略仅在候选预测开始前检查0.5 CPU秒预算，造成实际已超限仍按模型重排的情况。PR34在每次候选预测返回之后，以及最终选定方案之前再次检查。若超限，丢弃预测候选评分并执行已有 CP-SAT 第一合法方案。

**修复不能中断单次模型rollout**，所以计算耗时仍可能超过0.5 CPU秒；保证的是**不采用预算已经超限的学习模型重排行为**，不是单个机器wall-time的硬实时保证。

本PR正式编号为 #37（分支与源码实验内部仍保留 pr34 名称），从 PR33 Draft 分支堆叠。并行 [PR #36](https://github.com/lieuyimo/wm/pull/36) 基于另一批场景验证 PETS/MPC 累计轨迹代价与预算回退；本PR补充可控假时钟断言和五种模型权重的另一组独立预算回归。不覆盖PR32结果，不合并历史分支、不影响PR19。

## 测试方法与实验协议

1. [确定性 CPU 假时钟测试](../experiments/world_model_integration/online_horizon/test_pr34_budget_gate.py)：
   - 首方案耗时0.18s、第二候选完成后总CPU 0.66s且分数更高时，**必须放弃第二方案并回退CP-SAT**。
   - 两候选合计0.22s且第二方案更好时，允许正常改选。
   - 第一方案就超过0.5s时，不启动第二候选并安全回退。
2. 冻结的 [PR34实验协议](../experiments/world_model_integration/posttraining/pr34_protocol.json) 预先指定：**四类负载各6个全新场景seed，共24场景**，不与PR31～33 Train/Val/Test/研究场景重合；相同业务仿真器、CP-SAT、源权重、H20/P3、完成工序期望评分及随机键。
3. **五臂在线事实对照**：`cp_sat`、`rule_h20`、`original_v4_h20`、`warmstart_v4_h20`、`scratch_v4_h20`，每一组都真正执行完整样本转运业务并检查合法调度、机器人运动和资源占用。
4. 原 V4 与后训练两种权重严格使用PR31已归档权重和SHA256；Scratch由PR31**验证集**预先选中，未根据PR32测试重新挑选。CPU-only，0 GPU/0 新训练。
5. 每次完整记录实际决策CPU耗时和所采用的CP-SAT提案索引。若记录 `cpu > 0.5s` 且 `selected_index != 0`，CI直接报错，不能上报合格业务结果。

这也说明 **makespan与逾期作业指标不能混为一个综合胜负**：高负载原V4完成时间最快，Scratch逾期作业较少；shift 原V4完成时间较慢但逾期较少。

### 后训练相对原冻结V4的独立配对结果

- **medium**：Warmstart和Scratch均与原V4 **6/6持平**。
- **heavy**：Scratch相对原V4 **0胜/4平/2负**，平均 **+1.000 tick**；Warmstart **0胜/3平/3负**，平均 **+2.667 tick**。
- **shift**：Scratch **1胜/4平/1负**，平均 **−0.167 tick**；Warmstart **2胜/3平/1负**，平均 **−0.833 tick**。
- **light**：全部持平。

**后训练提高了独立服务事件概率精度，但至今没有稳定改善完整在线调度完成时间。** 在本批新场景中原V4-H20部分负载具有实测业务价值；这一结果不能被直接归纳为任何场景普适提升，且每负载仅6个新场景。

|---|---:|---:|---:|---:|

H20显著增大CPU成本。由于 `process_time` 而非wall计时，以及不可中断的单次候选rollout，本次**只验证预算后安全回退策略，不代表企业实时响应SLA已完成验证**。

## 下一阶段

1. **保留原V4作为在线世界模型参考权重**，新Warmstart/Scratch作为经过严格归档的研究候选；不再仅凭更低Brier增加训练轮次。
2. 针对独立新场景的动作排序、不同风险状态下的长时预测效用、模型置信度和限时推理策略做只读/先注册评估。将CP-SAT、Rule-H20与V4-H20区分，不把全部H20策略收益归于神经网络。
3. 如果要真正降低单次wall-time超时，应迁移有成熟实现的**有时限滚动规划或逐层缩短时域**方案，并单独冻结协议、对比CPU与真实响应时间。不得自行修改模型参数/仿真机制以使结果更好。
4. 再次训练时，沿用PR31已验证的完整环境、训练数据、优化器状态、RNG与best/latest权重保存协议；任何新模型均换独立权重和SHA。

**总裁决：预算执行完整性 GO；长时模型在部分合成高负载场景的决策价值有新证据；后训练稳定增益仍未成立。**
