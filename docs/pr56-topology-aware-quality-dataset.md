# PR56：公开拓扑条件下的高质量世界模型数据补充

## 起点和目标

[PR #55](https://github.com/lieuyimo/wm/pull/55) 使用原BusinessSimulator验证18个真实开发场景：原始2,024条完整t→t+1公开状态转移，旧前56步裁剪漏掉710条后续有事件的状态；24个设备故障、24个恢复；54次合法派单干预，18/18出现真实H20实体状态差，16/18出现真实最终完成时间差，0 GPU。两道数据质量门禁都通过。

但PR55仍然**只有原7×5无障碍地图**。无论如何改变工作站服务、机器人和任务释放，地图位置坐标固定并没有证明跨路线布局泛化。当前PR54/PyG R-GCN也只有实体位置坐标/任务/资源站点关系，缺少实际障碍/可行路线图，换布局而不暴露布局会形成伪不可观测性。

所以PR56做的不是“生成240份新场景”，而是**让地理拓扑成为世界模型可见的公开状态，先证明其安全、因果、动态覆盖与合法动作信息仍然存在**，通过再启动独立地图家族训练数据扩张。

## 12个开发场景，冻结前设计

- 3类已有动态压力机制：congestion、multi_fault、staggered_arrivals；
- 每类4种受控可通行障碍配置，共**12个真正不同seed的开发场景**。四种布局均出现在每类压力场景中；
- 固定原7×5实验室中5个工作站和3台机器人、原站点资源和合法任务工作流，改变唯一变量是静态walkability/导航拓扑。设备故障持续时间仍按原PR48环境真实私有配置，只用于生成实际事实，不给预测器读取。
- 四个预注册拓扑 `north_wall`、`south_wall`、`central_bottleneck`、`offset_barriers`，道路障碍精确坐标保存在`experiments/world_model_integration/topology_pr56/protocol.json`。
- 所有原机器人初始位置、home和站点都必须位于可走网格内，利用**原`Grid.shortest_path`与`Geometry.distance`**验证可达性与路线长短确实发生变化。**这里的“不同地图”是同尺寸不同障碍布局，不是跨尺寸、真实CAD/厂区地图或者不同机器人形态。**

## 实际公开世界模型拓扑输入接口

`pr56_public_map.py`只引用原仿真系统知道的`Grid`与`Geometry`，对每个公开观察构造：

1. `public_map`: 网格宽高、明确障碍坐标、按固定顺序列出的可通行cell、双向合法cell adjacency、每个map-cell的x/y归一化坐标和节点连接度。
2. `public_entity_to_map_cell_index`: 对当前**已公开存在**的机器人/工作站节点建立真实实体位置到可行网格cell的二部关系，其他未发布任务不能提前创建实体。
3. `station_geodesic_distances_ticks`: 从原Geometry的最短路线得到公开静态站点距离矩阵，避免用欧氏距离冒充可通行路径。
4. `topology_pyg_dual_graph`: 返回**原PR51实体+动作PyG图**、单独静态网格PyG图、实体到网格链接。当前是两张**原生PyG Data、未经新模型训练的输入桥接**。未来训练前必须另行实现可批量化的dual-graph encoder及节点/地图ID空间正确增量，不能宣称PR54 GRU已经使用了地图。
5. 目前的`public_map`在每个t是静态的，**所有t+1实际未来状态只存于`target`**。未知故障完成时刻、未来任务到达时刻和服务随机数仍在真实仿真器私有环境里。

这条路径复用现有PyG/RGCN组件，不重新设计一个脱离现有业务逻辑的路径规划器。最终目标是合法可重复执行的动作条件世界状态转移，不是训练独立Q或候选评分器。

## 完整真实数据与动作配对

`pr56_trial.py`对每组场景实际执行原`BusinessSimulator.run`，同时调用：

- `PublicTransitionCollector`收集从t0直至该episode真正终止的**全量连续公开状态**，包含t−3..t真实历史/当前已执行合法动作与t+1可观测业务结果，绝不再固定截取前56步。
- `EntityTruthBranch`在原CP-SAT有两个以上真实不同合法派单候选时选最早[7,70]的公开锚点，先执行首个方案，再从**完全相同的真实原场景种子、锚点前公开历史、候选池**逐一重跑其余候选，并只在锚点改变一次合法派单方案。
- 从真实`_future_nodes`标签对比H5/H20当前可见实体状态和匿名未来新任务事件计数，再对比真实完整makespan；每一条真实分支均经过既有资源容量、路径运动与工序生命周期安全审核。
- 干预后的执行顺序可能改变随机过程抽样顺序，所以这里验证的是配对**真实仿真信息量**，不宣称完全固定所有外生潜在结果。没有替换原V4、CP-SAT、PR19和所有旧训练checkpoint。

## 预注册质量裁决，不根据结果修改门槛

`pr56_gate.py`对三个来源的`source_head.txt`、`SHA256SUMS`及完整12场景原始JSON再核验，自动输出 `PASS_TO_PRE_REGISTER_NEW_MAP_DATASET` 或 `NO_GO_BULK_CROSS_MAP_DATA_EXPANSION`。

必须满足：12个源场景/4个障碍拓扑/每拓扑3个stress、原始全时序连续、全部真值完整、0安全违规、公开模型确实看到地图连接信息、地图与无障碍地图至少一处真实路线距离不同、真实故障和恢复各至少12个、旧56步之后存在真实事件变化；最少**9/12**场景有多个合法派单候选且H20存在可测的实体未来差异，至少**6/12**场景有合法动作导致真实makespan差异。

如果任何门槛失败：必须如实保留数据和NO-GO原因，不能删除困难实例、改阈值或者把失败分类简单扔到“不可用”。**通过仅允许设计新的数据批次，不构成模型泛化证据或240场景批量许可。**

## 下一阶段合理扩充的准入步骤

1. **拓扑外推划分**：单独冻结更丰富的新拓扑家族、训练地图和验证地图，以及绝不用于设计调整的真正盲测OOD地图。PR56的4幅地图均为**开发地图**，不能用来充当新盲测地图。
2. **双图世界模型接线与批量正确性**：未来模型需要显式消费`map PyG`及实体关系图，并能在多图batch中正确完成map/entity索引移位，完成梯度单独回传测试。不得用未来私有路线风险作为预测器特征。
3. **CPU分阶段实际场景扩容**：约60→120独立TRAIN场景，按动态质量、重复率、真实合法动作效应及每类地图瓶颈覆盖统计评估边际价值。若信息不足继续补缺口，不机械拉到240。
4. **自然分布的完整验证与OOD测试**：训练可基于真实下一步标签为稀有事件分层采样，但新VALIDATION/TEST不可按t+1目标筛选样本；独立测试的地图家族、case seed、随机数必须预先封存。
5. **神经世界模型学习才用GPU**：对比原PR54 snapshot/history，增加双图地图信息和真正单步可递归状态转移，报告设备Brier、H5/H20公开状态误差/物理合法性及线上调度收益。GPU任务单独保留在 [Issue #54](https://github.com/lieuyimo/wm/issues/54)。

所有研究入口见`topology_pr56/`与`.github/workflows/pr56-public-map-quality.yml`。研究数据是合成仿真，不代表迈克生物真实机器人生产记录。

**原运行全部运动/工作流/资源安全审计通过**。第二版只修正了实验审计中的一个措辞错误：**“到260 tick未完成”不是“运动安全违规”**。修正后的质量报告分别记录`actual_motion_resource_workflow_safety_verified=true`和`all_matched_legal_branches_completed_for_uncensored_makespan=false`，不改变任何既定质量阈值、任务地图或真实业务规则。被截尾的`260 tick`不能当作完整makespan真值；即使不同候选时间到上限，也不提供有效完工时间排序监督。

因此正式质量判定为 **`NO_GO_BULK_CROSS_MAP_DATA_EXPANSION`**，失败项明确为“12场景中未全部完成”和“部分合法干预分支未全部完成”，**不允许直接生成240份场景**。未完成的完整原始公共时序仍可作为动态学习的受限/截尾数据，但必须与完工已知样本区分，绝不直接删除难样本、伪造完成时刻或在原方案中放宽门槛。

2. 把数据拆为**可完整定义H20/最终makespan的对照**和**仅保留t+1/H5/H20状态部分真值及右截尾标记的困难负载**，两类均留原始SHA和状态时间线。对后者不能把时间上限视为真实完成成本。
3. 保留前一步成功建立的`public_map` + PyG双图公开输入路径；只有新双图世界模型显式消费地图、模型seed/验证集和跨未见地图评估协议冻结后，才开始大规模训练。旧PR54 RGCN并未接入地图张量。
4. 后续完整新数据集先冻结不同地图家族的TRAIN/VALIDATION/TEST隔离，**而不是将这4个已开发的7×5布局冒称未见OOD测试**；训练先逐批，证实真实状态增量信息和动作H20有效性后再考虑扩到60/120/240。
