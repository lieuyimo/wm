# PR26：V4 服务事件 + pgmpy 运输风险联合世界模型（真实实现）

## 方法边界与架构

- 服务动态：**冻结 V4**，`HybridSystemWorldModel` 已有合法 `WorkflowDynamics`；
- 运输风险：**开源 pgmpy 1.0.0**，使用 PR25 的真实训练 CPD，按当前/预测公开状态查询运输段超基线延迟概率；
- 不确定性传播：借鉴 Chua 等 PETS (2018) 的有界粒子轨迹采样思想，但未复现 PETS 的连续动力学网络或 CEM，保持原 RHWM 3 粒子、H1/H5/H10 接口；
- `shadow`：将学习的运输风险作为可查询事件侧通道，完整状态**严格等于同种子 V4**，不能宣称它会改善物理状态预测；
- `sampled_hold`：**明确标记为实验性事件时间适配**，每个新运输段只抽一次 pgmpy 延迟事件，按训练集中正延迟均值用停留时间近似，再由既有状态引擎计算下一步。后处理要求再次通过 `check_business_transition` 校验，冲突停顿不允许引入碰撞。**这是工程适配，不是原论文已证实的正确随机时间分布。**

两种模式均为实验接口，未接正式生产路径、未修改旧 V4 权重、未更改业务规则或运动规划器。

## 裁决

- **可选的运输风险通道 GO**：存在独立事件概率预测，已与 V4 共同对动作候选进行有界预测，风险可用于调度器辅助评分。
- **将随机停顿加入正式运动状态转移 NO-GO**：没有取得 H10 整体状态准确率改善；当前几何路径规则预测的时间 MAE 在 PR25 更低。实验适配留作显式离线研究，默认采用 `shadow`。
- 不得把 `shadow` 的 V4 状态误差写成“联合模型提高了完整状态预测”；风险价值需在 PR27 同一场景、同一随机条件、同一 CP-SAT 候选集下检验对决策选择是否有稳定收益。
