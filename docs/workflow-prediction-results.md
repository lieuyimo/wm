# 完整业务工作流预测与决策评价

## 结论与适用范围

新业务适配器能够在模型预测某个已知阶段完成后，在下一观测边界按公开模板生成后继阶段，并继续递归预测。确定性单机器人三阶段测试从第 0 步独立推演至全部完成，16 步中的动作、阶段状态、释放时刻及机器人状态与事实轨迹一致；该测试不代表随机服务下的预测准确度。

本轮确认集包括 8 个完整场景、4 个地图/种子簇。旧固定实体适配器在事实轨迹的 **27/27 次**后继阶段释放中均未生成对应阶段；其中规则模型有 21 次已正确预测前一阶段完成，仍然缺失后继。新机制的释放由确定性业务规则实现，不是神经网络学会了工作流。

在抽取的 16 个同状态候选决策点上，单独更换评分没有改变排序或选中动作；同时更换预测和评分在 1 个决策点改变了选择，该点独立重放的完整业务平均流转时间相同。完整闭环中，新规则方案相对旧规则方案 1 个场景改善、7 个相同。PETS 与结构化模型没有表现出稳定的闭环优势。决策点来自同一场景的轨迹，不能当作独立统计样本；4 个种子簇也不足以作广泛推广。

## 实现及信息边界

- [`WorkflowDynamics`](../business_transport/dynamics.py) 复用既有服务与运动预测，并调用 [业务状态转移](../business_transport/workflow_transition.py)。在第 `t` 步预测某个已知任务完成时，后继阶段在 `t+1` 的预测观测中以 `waiting`、`robot_id=None` 出现，随后才能被调度。最终阶段完成后不再释放；上一个阶段保持完成。
- 后继的 `job_id`、流程名、阶段编号和站点来自当前已观察任务与 `PublicBusinessRules.workflows`，样本类型、包装、温度条件、期限等从当前观测继承。配置编译器现在将明确配置的这些可观察属性传递给事实各阶段；不读取未来业务任务表、未来设备故障或服务剩余倒计时。
- [业务校验器](../business_transport/workflow_transition.py)只对合法后继放宽实体集合，仍调用原有通用校验器核验既有实体。它拒绝未知、提前、重复的阶段，以及删除或篡改已知任务、非法并行、机器人冲突和资源容量不一致。容量关系继续通过既有 `rebuild()` 和 `capacity_view()` 重算；旧 `CapacityDynamics` 保留原行为供历史对照。
- [`WorkflowPolicy`](../business_transport/policy.py) 是启用完整业务递推与新评分的入口；也可以对 `BusinessPolicy` 显式设置 `workflow_prediction=True, scoring='workflow'`。旧默认行为和原 `workload_score()` 保留。执行与预测均可复用 PR #14 的不可变 LaCAM3 恢复快照；新增阶段分支的缓存隔离与任务变化失效均有测试。

预测过程中未来外生任务、未知设备状态变化和未来动作不是事实输入。事实评估及反事实回放仅在离线产生标签；不同候选的完整结果由相同事实前缀和相同外生条件下的独立仿真产生。归档的事实观测没有服务剩余倒计时，真实的后续事实仅作为离线评价标签。

例如，对已有 `business` 场景及本地构建好的 `pibt_library`、`lacam_worker`，规则模型可按以下方式接入；换用 PETS 或结构化头时，同时将策略名改为 `cpsat_pets` 或 `cpsat_structured`，运动适配器与业务转移保持相同：

```python
from business_transport.lacam3_integration import HybridBusinessSimulator, RecoveryMovementModel, RecoveryObserver
from business_transport.policy import WorkflowPolicy
from lab_transport.dynamics_model import Geometry
from lab_transport.torch_structured_adapter import ProgressAwareRule

geometry = Geometry(business.scenario.grid)
observer = RecoveryObserver()
movement = RecoveryMovementModel(ProgressAwareRule(geometry), geometry, business.rules,
                                 pibt_library, lacam_worker)
policy = WorkflowPolicy('cpsat_rule', geometry, business.rules, observer, movement, seed=20261109)
simulator = HybridBusinessSimulator(business, 'world', 71003, motion_backend='hybrid',
                                   pibt_library=pibt_library, lacam3_worker=lacam_worker)
result = simulator.run(dispatch_policy=policy, on_observation=observer.observe)
```

## 新旧评分及候选动作

新评分对起始观测中已知的**业务任务**计数，而不是把同一任务的每个阶段当作独立工作：

1. 窗口内每个尚未完成最终阶段的任务，每步计 1。
2. 窗口末加上剩余运输距离与预计服务步数；未释放但属于已知任务的阶段只使用公开路线和站点服务先验。可见有效服务进度可扣除，未知进度不伪装成真值。
3. 工作站共享资源的竞争代理与距离依次用于平局判断，不再把同一次等待作为额外成本重复累加。

距离、服务步数和未完成时间的系数均为 1，延续原评分的名义步数解释，并非真实实验室成本或事后搜索的权重；竞争代理不是 FIFO 队列。公式与窗口、候选预算、场景划分在实验前固定，详见[冻结协议](workflow-prediction-protocol.md)。

确认集的固定候选消融：旧预测/旧评分、旧预测/新评分、新预测/旧评分和新预测/新评分共享相同 CP-SAT 候选。16 个状态中，单独更换评分有 **0 次**排序变化；其主分数变化在每个状态下对所有候选都是相同偏移。单独更换阶段递推使 **1 次**候选排序和动作选择变化，独立分支的完整平均流转均为 **34.67 步**。这说明所抽取状态中新增后续工作量经常还不能区分候选，不能据此证明新评分普遍无价值。PETS、结构化模型分别使 3/16 个状态的候选排序变化，但最终选择均与新规则模型一致。

## 预测结果：已见地图的新任务表

下表是动态业务联合状态：同时要求当前已知业务阶段的 ID、流程、状态和属性、机器人位置/任务，以及可观察工作站占用关系正确。窗口重叠，数字用于诊断而不是独立样本显著性检验。

| 模型 | 一步联合正确 | 三步联合正确 | 五步联合正确 |
|---|---:|---:|---:|
| 规则 | 121/137（88.3%） | 72/103（69.9%） | 55/83（66.3%） |
| PETS 混合 | 116/137（84.7%） | 49/103（47.6%） | 32/83（38.6%） |
| 结构化服务头混合 | 104/137（75.9%） | 34/103（33.0%） | 23/83（27.7%） |

一步服务完成事件中，规则预测正确 **38/50** 个、共预测 42 个；PETS 正确 **40/50** 个、共预测 53 个；结构化头正确 **36/50** 个、共预测 58 个。PETS 在这组一步事件上的召回较高，但误报也增加，不能由此认定决策更好。五步窗口内对应正确事件数为规则 **43/75**、PETS **17/75**、结构化头 **5/75**；多步递归、先前预测分歧与实际服务时间共同影响结果，不能把全部误差单独归因于随机性。

对于确认集一步窗口中实际发生的 26 次后继释放，规则在正确时刻预测 20 次，PETS 和结构化头各预测 26 次，但它们分别还预测了 29 和 31 次释放。五步窗口的同刻释放分别为 **8/17、5/17、0/17**。当当前可观察状态及服务完成事件均与事实一致时，各模型检查到的阶段释放逻辑错误和资源关系错误均为 **0**；这并不意味着模型预测的服务时间总是正确。

窗口口径固定：一步共有 614 个候选窗口，其中 578 个符合“无未知外部到达和设备状态变化”等条件，选择 137 个；三步为 598/429/103，五步为 582/340/83（候选/合格/选中）。选中窗口中包含未完成多阶段任务的分别为 **113、85、67** 个；所有合格且发生后继释放的窗口均被纳入。其余排除原因和每个窗口的实际/预测事件见机器可读记录。

原固定实体联合指标继续按旧 `eligible_windows()` 的分母报告；确认集一步规则/PETS/结构化分别为 **78/86、73/86、71/86**，五步分别为 **28/34、22/34、20/34**。该旧指标与上表业务动态联合指标的定义和窗口选择不同，不能直接比较百分比。

## 完整调度闭环和成本

五组使用相同场景、外生扰动和运动执行器；后三组使用同一 CP-SAT 候选预算、5 步、3 粒子、工作流评分和业务转移。完整任务流转均以业务任务为单位；本确认集中全部任务完成，因此平均流转与受限流转相同。

| 方案 | 完成任务 | 平均流转（步） | 平均 / P95 决策墙钟（ms） | 每次模型预测平均墙钟（ms） |
|---|---:|---:|---:|---:|
| 最近优先 | 48/48 | 44.85 | 0.17 / 0.65 | 无模型 |
| CP-SAT + 规则 + 旧转移/旧评分 | 48/48 | 43.13 | 52.70 / 123.38 | 1.16 |
| CP-SAT + 规则 + 新转移/新评分 | 48/48 | 42.98 | 67.71 / 146.09 | 1.35 |
| CP-SAT + PETS + 新转移/新评分 | 48/48 | 43.54 | 76.81 / 160.57 | 1.55 |
| CP-SAT + 结构化头 + 新转移/新评分 | 48/48 | 43.63 | 91.22 / 185.03 | 1.97 |

模型预测耗时包括服务预测、规则运动和对应业务状态构造；决策耗时还包括 CP-SAT、多个候选/粒子、状态校验与评分。上述是本次本机 CPU 墙钟测量，不是 GPU 测试或实时性保证。对规则方案，新机制平均每次模型预测约增加 **0.19 ms**，平均完整决策约增加 **15.00 ms**；这两个量的分母不同，不能直接相减或相加。PETS 和结构化头分别真实调用 **2,038** 和 **2,082** 次。

相对于新规则方案，PETS 和结构化头各有 **1 个场景较快、4 个相同、3 个较慢**。按地图/种子簇配对的受限流转差值分别为 +0.375 和 +0.431 步；两者的分层 bootstrap 区间均跨 0，且仅有 4 个簇，证据不足以证明收益。新规则相对旧规则的 1 个改善场景平均减少约 1.17 步/任务，其余相同；不能将该单例归因于评分本身。阶段等待、设备等待、资源忙碌和每场景完整结果见 `summary.json`；未完成任务在其它可能场景中按截止时已发生的流转计入受限均值。

所有确认场景未检出资源超容量、顶点碰撞、交换边、非法边、锁定机器人移动、重复分配或非法生命周期；模型预测回退为 0。此为离散仿真检查，不是连续物理环境的安全证明。

## 数据、测试与局限

开发集沿用 6 个既有场景；确认集在相同两张公开地图上使用 4 个新种子簇、8 个工作负载/容量/故障场景。对既往 PR #12 的任务表逐一检查后，确认集任务表无重复；地图本身并非未见过，参数均为仿真假设。两套场景各完整运行两遍，比较时仅排除实测耗时。试运行中发现的站点服务关系错误和无序浮点累加造成的重复比较失败均已修复；原记录及失败日志保留，没有根据确认集调整权重、阈值或模型。

本地原有 **165** 项测试及新增 **18** 项测试通过；PR #14 的原后端、PIBT 和 LaCAM3 的 22 场景双次历史回归再次通过。新增确认的样本属性编译、三阶段无事实未来递推、容量阻塞、异常暂停、动态 ID 约束、缓存隔离和安全回退均有自动测试。执行命令见[证据说明](../examples/evidence/workflow-prediction-20261110/README.md)，CPU GitHub Actions 在本 PR 中执行。

当前证据支持把完整业务递推作为系统正确性修复；**不支持宣称学习模型已经改善调度**。已有结果主要来自已见地图、有限种子、5 步窗口和固定候选预算。下一步若继续模型研究，应先检查候选之间为什么很少在预测窗口内产生可利用的后续阶段差异，并收集更有代表性的真实业务配置及服务历史；本轮没有重新训练模型或引入新架构。
